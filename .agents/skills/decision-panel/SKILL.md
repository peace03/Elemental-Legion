# 의사결정 패널

세 안을 독립적으로 만들고 분야별 평가를 모아 개선안을 제시한다. 메인은 이 절차를 직접 진행한다. 적용 조건은 [AGENTS.md](../../../AGENTS.md), 담당 역할은 [패널 역할 배정](../../../Docs/Rules/subagents.md#의사결정-패널-역할-배정)을 따른다.

## 안건 준비

- 결정할 질문, 원하는 결과, 범위, 필수 조건, 근거 자료를 짧게 정리한다. 사용자 의도나 평가 기준을 바꾸는 불명확함은 먼저 확인한다.
- 안건에 영향을 받는 분야와 분야별 평가 기준을 제안 결과를 보기 전에 정한다. 사용자가 지정한 분야와 우선순위를 반영한다. 예를 들어 전투 경보를 비교할 때 개발은 판정과 구현 비용, 그래픽은 가독성, 기획은 플레이어가 알아차리고 대응하는 흐름을 본다.

## 1. 독립 제안

서로 다른 서브에이전트 **3명**에게 동일한 안건·조건·자료를 준다. 새 컨텍스트로 호출하고 다른 제안이나 예상 순위를 전달하지 않는다. 각각 안 하나와 작동 방식, 이득, 부담, 핵심 가정을 제출한다. 작동 방식이 겹치면 해당 제안자에게 자신의 안과 다른 방식으로 보완을 요청한다. 이때도 다른 안의 내용은 전달하지 않는다. 메인은 세 응답을 받은 뒤 `A`, `B`, `C`로 구분한다.

## 2. 분야별 평가

- 제안과 별도로 분야마다 담당 서브에이전트를 생성한다. 각 담당에게 동일한 세 안과 자기 분야의 기준을 주고 다른 평가자의 점수는 전달하지 않는다.
- 담당자는 자기 분야에서 **세 안 모두**를 평가한다. 안마다 `장점`, `단점`, `점수(0~10점)`, `점수 근거와 가정`, `필수 조건 충족 여부`, `보완 제안`을 적는다. 0점은 해당 기준을 충족하지 못함, 5점은 큰 보완이 필요함, 10점은 근거를 바탕으로 충분히 충족함을 뜻한다. 확인이 필요한 조건은 표시하고, 필수 조건 위반은 점수와 별도로 기록한다.
- 분야별 평가자 **총수에 별도 상한을 두지 않는다**. 동시 실행 상한에 맞춰 완료 응답을 회수하고 남은 분야를 다음 묶음으로 호출한다. 필요하면 현재 도구가 지원하는 방법으로 완료 스레드의 슬롯을 정리한다.
- 요청한 분야와 A·B·C 평가를 대조한다. 누락이나 범위를 벗어난 점수는 해당 담당에게 보완을 요청한다. 호출이나 보완이 막히면 누락된 분야·안과 사유를 명시한다. 점수를 대신 채우거나 미완료 평가를 완료로 처리하지 않는다.

## 3. 종합과 개선

세 제안과 필요한 분야의 평가가 모두 모이면, 제안과 평가에 참여한 인스턴스와 별도로 새 `specialist`를 호출한다. 안건과 필수 조건, 세 제안, 각 분야의 장단점·점수·근거를 전달한다. `specialist`는 점수 차이를 만든 이유와 분야 간 충돌을 검토하고, 장점은 살리고 단점은 보완한 개선안 한 개를 만든다. 필수 조건에 어긋나는 부분은 수정하거나 미해결 조건으로 표시한다. 원안의 평가 점수는 원안에 표시하고, 변경된 개선안에 추가로 확인할 항목을 적는다.

메인은 개선안을 먼저 보여 주고, 세 안의 요약, 분야별 점수와 주요 장단점, 개선안에 반영한 내용, 남은 확인 사항을 붙인다. 사용자가 방향을 확정하면 해당 작업의 구현 절차로 넘긴다.
