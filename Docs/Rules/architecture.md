# 아키텍처 규칙

## 서버 권위

- 서버가 모든 상태를 계산한다. 클라이언트에는 게임 규칙 로직을 두지 않는다. 예외는 내 군단 중심점의 예측 이동 하나다.
- 클라이언트는 이동 방향, 양성 원소, 건설 격자 칸 등 **명령 의도**를 보낸다. 서버가 실제 위치, 피해와 실행 결과를 계산한다.
- 서버는 모든 명령을 검증한다: 자원, 해금 단계, 쿨타임, 인구 상한, 초당 명령 수(`server.commandRateLimitPerSecond`). 실패한 명령은 무시하고 사유 코드를 돌려준다.

## 틱과 순서

서버 틱은 `world.tickRate`(20Hz, 50ms)로 고정한다. 한 틱은 이 순서로 실행한다.

1. 기한이 된 건설 완공과 입력 적용
2. 군단 이동과 기지 충돌 처리
3. 진형 슬롯 갱신과 아군 원소 사이 간격 보정
4. 가장 가까운 유닛과 공격 가능 건물 탐색
5. 공격, 상태이상, 시너지 반응, 타워 공격
6. 사망과 중립 즉시 전향·PvP 후보 생성, 핵 드롭, 건물 파괴·본진 패배·유령 만료
7. 양자 이동 완료와 후보 만료·확보·구출 판정
8. 양성, 중립 재생성, 맵 핵 생성·습득
9. 클라이언트별 시야 계산
10. 스냅샷 생성과 전송

PvP 후보는 만료를 먼저 정리한 뒤 확보·구출을 판정한다. 후보의 분대 예약은 전역·소유 인구 예산과 함께 관리한다. 양성 완료·중립 재생성은 후보 처리 뒤 진행한다.

`SimCommand`의 접수와 실행을 구분하고 실행 결과는 본인에게 전달한다. 봇은 `WorldView`에 담긴 자기 상태와 시야만 읽는다. 전투 이벤트도 현재 시야로 거르고 보이지 않는 원인 유닛과 건물 ID는 제거한다.

## 시야와 전송

- 시야 밖 정보는 클라이언트로 **아예 보내지 않는다**. 이것이 맵핵 방지의 핵심이다.
- 내 유닛, 본진, 완공 시설은 `world.visionRadius`의 원형 시야를 제공한다. 접속한 플레이어는 서버가 확정한 군단 중심의 `world.battleCameraVision` 직사각형도 볼 수 있다. 공간 정보와 독립적인 접속 순위는 플레이어 ID와 합산 점수만 전역 공개한다.
- 탐색 기록은 `world.visionCellSize` 크기 칸의 비트맵으로 두고 변경분만 보낸다.
- 전송 주기: 군단 중심 `server.snapshot.legionHz`, 유닛 상대 좌표 `server.snapshot.unitHz`(2바이트 양자화).
- UDP의 사망, 전향, 핵 드롭, 시너지 반응, 채팅은 **신뢰·순서 보장 채널**로, 위치 스냅샷은 비신뢰 채널로 보낸다. 온라인 WSS에서는 대기 중인 위치 데이터의 최신 묶음만 보관한다. 시야 변경과 명령 결과는 순서대로 보내고 큐 상한을 넘긴 연결은 종료한다. [프로토콜](../protocol.md)
- 채팅은 시뮬레이션과 분리된 처리 경로를 쓰고, 근접 채팅은 서버가 위치를 보고 반경을 걸러 보낸다.

## 공유 코드

- `shared/`는 UnityEngine을 참조하지 않는다. 좌표는 `System.Numerics.Vector2`(XZ 평면)를 쓰고, 클라이언트에서 Unity 좌표로 변환한다.
- 단위: 거리는 미터, 시간은 초, 속도는 m/s.
- 시뮬레이션은 단일 스레드에서 돈다. 난수는 월드가 가진 시드 기반 RNG 하나만 쓴다(테스트 재현용).
- 계정과 저장은 인터페이스(`IAccountStore`, `IWorldStore`)로 분리하고, 지금은 파일 구현만 만든다.

## 인터넷 방 서버 승계

- 중계가 방의 수명과 증가하는 호스트 세대를 관리한다. 플레이어 WSS 연결을 유지하며 해당 세대의 서버 연결만 교체한다. 정상 퇴장은 최종 틱에서 인계하고, 장애는 최신 검증 백업으로 복구한다. 마지막 사람 참가자가 나가면 AI 수와 관계없이 방을 종료한다.
- `CaptureMigrationState`·`RestoreMigrationState`는 명령 대기열·난수·AI와 진행 중인 작업을 정확히 보존한다. 디스크 복원의 유령 전환·작업 취소와 분리한다. 캡처는 틱 경계에서 독립된 복사본을 만들고 압축·직렬화·전송은 틱 밖에서 수행한다.
- 전체 월드는 중계가 선택하고 인증한 차기 **서버 역할**에만 별도 백업 연결로 전달한다. 플레이어 게임 연결에는 계속 시야 필터를 적용한다. 계정 복귀 키와 중계 비밀값은 백업에 넣지 않는다.
- 후보는 실제 월드를 복원한 뒤 준비를 확인한다. 세대 확정 후 실패하면 이전 서버를 재개하지 않고 다음 후보·세대로 복구한다. 예측·복제·사건 버퍼는 새 세대에서 초기화하고 완성된 기준 상태를 한 번에 표시한다.
- 주기와 제한 시간은 `server.hostMigration`을 사용한다. 프레임·백업·권한 형식은 [프로토콜](../protocol.md#인터넷-방-서버-승계), 실행과 상시 중계 전환은 [README](../../README.md#온라인-서버-운영)를 따른다.

## 데이터 테이블

- 모든 게임 수치는 `shared/Data/gamedata.json`에서 읽는다. 코드에 숫자를 직접 쓰지 않는다.
- 수치가 필요한데 JSON에 없으면 키를 추가하고 `_meta.placeholderPaths`에 경로를 넣은 뒤 작업 보고에 적는다.
- **이미 있는 밸런스 수치는 요청 없이 바꾸지 않는다.** 밸런스는 기획자의 결정이다.
- `_`로 시작하는 키(`_meta`, `_comment`)는 설명용이며 로더가 무시한다.
- 접속할 때 서버와 클라이언트는 gamedata.json의 SHA-256 해시(줄바꿈을 LF로 정규화한 바이트 기준)를 비교하고, 다르면 접속을 거부한다.
- 원소는 영문 id(`water`, `dark_matter` 등)로 다루고, 화면 표시는 `displayName`을 쓴다.

## 봇

- 서버 봇은 `BotBrain`으로 판단하고 사람과 같은 명령 검증을 거친다. 부하 측정용 봇은 중립 사냥, 양성, 적 접근과 순찰을 수행한다.
- 대기실 AI는 시작 인원과 정원에 포함된다. 서버는 AI마다 독립 군단을 만들고 시야와 자기 상태를 전달한다. AI는 관측한 정보를 바탕으로 포집·양성·분대 이동·양자 이동·후보 확보를 판단한다. 호스트 승계는 판단 상태까지 이어 가고, 디스크 저장은 AI 소유자 ID와 난이도를 복원한 뒤 새로 판단한다.
- 방장은 대기실에서 AI마다 쉬움·보통·어려움을 선택한다. 판단 주기는 JSON `ai`에서 읽고, 어려움은 관측한 적의 상성에 맞춰 양성하며 군단 체력이 낮으면 본진으로 후퇴한다. 자원·전투 능력치·시야 보너스는 주지 않는다. 소유자 순서별 난이도를 저장하고 승계 시 판단 주기와 후퇴 상태도 보존한다. M0 부하 봇의 매 틱 판단은 유지한다.
- 2026-11-03에 RTS AI 설정과 메시지 전송 방식을 비교했다. 기존 `BotBrain`이 게임 규칙과 관측 범위를 사용하고 기존 전송 계층이 대기실 상태를 이미 전달하므로 두 경로를 재사용했다. [OpenRA AI 규칙](https://github.com/OpenRA/OpenRA/blob/bleed/mods/ra/rules/ai.yaml) · [LiteNetLib](https://github.com/RevenantX/LiteNetLib)

## 클라이언트

- 이펙트와 사운드는 서버 이벤트를 받아 재생하는 표현 전용이다. 이펙트 결과가 게임 상태에 영향을 주면 안 된다.
- 직접 이동 입력이 있거나 서버 확인을 기다리는 입력이 있는 동안 선택 분대의 중심만 예측한다. 그 외 이동은 원소와 중심을 `server.interpolationDelayMs`의 같은 시점에서 보간한다. 카메라는 서버에서 최근 확정한 중심을 따라가며 별도로 움직임을 완화한다.
- 메인 카메라는 전장 지형을 표시한다. 1~3번 분대를 선택하면 해당 중심을 따라가고, 4번 수비대 선택과 B 본진 확인은 본진을 보여 준다. B는 기존 분대 선택과 명령을 바꾸지 않는다. 빈 분대도 중심을 움직이고 카메라가 따라가지만, 추가 직사각 시야는 본진을 기준으로 한다. 빈 중심의 충돌·우회에는 자기 건물과 직전 완성된 관측의 건물만 사용한다. 증원이 건물을 관측하면 가까운 합법 경계로 중심을 보정하고 이동 revision을 갱신한다. 화면 비율과 기울기를 반영해 화면에 비치는 지면을 서버 카메라 시야에 맞춘다. 미니맵을 클릭해 화면만 옮길 수 있으나 서버 시야의 기준은 인증된 자기 분대 1~3 또는 본진 4 중 하나다. 임의 좌표로 서버의 관측 범위를 늘리지 않는다. 유닛·시설의 원형 시야는 모든 자기 유닛과 완공 시설에서 유지하고, 추가 직사각 시야는 기준 하나만 사용한다. 유닛과 시설은 서버가 허용한 관측만 표시한다. 현재 시야·지난 탐색·미탐색은 미니맵에서 구분한다. [Unity 직교 카메라](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Camera-orthographicSize.html) · [Mirror 공간 격자 참고](https://github.com/MirrorNetworking/MirrorDocs/blob/main/manual/interest-management/spatial-hashing.md)
- 양자 이동의 배치와 취소·성공은 서버가 판정한다. 자기 귀환 슬롯을 클라이언트 건설 미리보기에서 사용하고, 상대의 시전·대기·예약 구역은 보내지 않는다. 순간 이동은 유닛과 분대의 `MovementRevision`을 증가시켜 예측 이력을 지우고 과거 위치와 보간하지 않는다. 디스크 유령화는 시전을 취소하고 성공 대기는 유지하며, 호스트 승계는 진행 중 시전과 미적용 명령까지 정확히 복원한다. 일반 디스크 복원은 스키마 3만 허용한다. 지원 v1 JSON은 명시적으로 별도 업그레이더를 호출할 때만 스키마 3으로 변환한다.
- 게임 판정에 Unity 물리를 쓰지 않는다.

## 하지 말 것

- 클라이언트가 보낸 위치·피해·결과를 믿지 않는다.
- 시야 밖 정보를 클라이언트로 보내지 않는다.
- 게임 수치를 코드에 직접 쓰지 않는다.
- 요청 없이 기존 밸런스 수치를 바꾸지 않는다.
- `shared/`에서 UnityEngine을 참조하거나 C# 10 이상 문법을 쓰지 않는다.
- 게임 판정에 Unity 물리를 쓰지 않는다.
- 외부 코드·에셋은 [조사와 활용 기준](reuse.md)에 따라 검증하고 도입한다.
