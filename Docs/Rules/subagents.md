# 서브에이전트 균형형 운영 규칙

메인은 사용자 의도 확인, 작업 분할, 결과 통합을 맡는다. 요구가 확인된 뒤 독립적으로 분리할 수 있는 기획·조사·구현·검증·리뷰는 아래 역할에 위임한다. 작은 단일 수정은 메인이 직접 처리할 수 있다.

## 역할별 설정

| 작업 | 역할 | 모델 | 추론 수준 |
| --- | --- | --- | --- |
| 코드·Graphify·공식 자료 조사 | `explorer` | `gpt-6-luna` | `high` |
| 단순 문서·목록·변경 내용 정리 | `documenter` | `gpt-6-luna` | `low` |
| 게임 기획·아이디어 발상·플레이 검증 설계 | `game_designer` | `gpt-6-astra` | `high` |
| 범위가 명확한 Unity·.NET 기능, Blender 자동화·그래픽 도구·일반 셰이더 코드 | `implementer` | `gpt-6.1-sol` | `medium` |
| 전투·시뮬레이션·패킷·저장·성능, 복잡한 렌더링 구조 | `core_engineer` | `gpt-6.1-sol` | `high` |
| Blender·Unity 그래픽 자산 제작과 화면 연출 | `graphics_artist` | `gpt-6.1-terra` | `high` |
| Blender 메시·리깅과 Unity UI·VFX 등의 시각 검토 | `visual_reviewer` | `gpt-6.1-terra` | `high` |
| 정해진 빌드·테스트 실행과 결과 정리 | `validator` | `gpt-6-luna` | `medium` |
| 구현과 독립된 코드 리뷰·회귀 위험 검토 | `reviewer` | `gpt-6.1-sol` | `high` |
| 어려운 설계·보안 문제·원인 불명 오류 분석 | `specialist` | `gpt-6-astra` | `high` |

실제 기본값은 [프로젝트 설정](../../.codex/config.toml), 역할별 값과 지침은 [역할 파일 폴더](../../.codex/agents/)에서 관리한다. 역할을 지정하지 않은 서브에이전트는 `gpt-6.1-sol / medium`을 기본으로 사용한다. 설정과 표를 함께 갱신한다.

## 게임 기획과 아이디어 발상

- 메인은 원하는 플레이 경험, 적용 범위, 제약을 확인해 `game_designer`에게 전달한다. `game_designer`는 [기획 요약](../design-summary.md)과 [게임 규칙](gameplay.md)에서 작업에 필요한 부분을 확인한다.
- 원소 조합, 새 모드, 성장 방식 등을 기획할 때 플레이어에게 서로 다른 선택을 주는 안을 제안한다. 각 안의 플레이 흐름과 상대의 대응, 차별점, 기존 규칙과 밸런스에 미치는 영향, 구현 부담을 비교한다. 가정과 확인한 사실을 구분하고 작은 시제품에서 확인할 플레이 조건과 판단 기준을 제시한다.
- `game_designer`는 지정된 기획 문서와 검증 계획을 작성한다. 방향을 바꿀 수 있는 질문은 메인에 전달한다. 메인이 사용자와 방향을 확정한 뒤 코드·씬·게임 수치 변경을 구현 담당에게 넘긴다.
- 기획 설명과 검토 자료는 독자가 판단할 질문에 맞춰 작성한다. 표현 방식과 가독성 기준은 [기획 설명과 시각화 규칙](design-communication.md)을 따른다.

## 그래픽 작업 분담

| 작업 범위 | 담당 역할 |
| --- | --- |
| Blender 모델링·리깅·웨이트·UV·재질·조명, Unity 재질·Shader Graph·조명·후처리·VFX·씬 연출 | `graphics_artist` |
| 재사용할 Blender 자동화 스크립트·Unity 그래픽 도구·일반 셰이더 소스 코드 | `implementer` |
| 여러 시스템에 영향을 주는 렌더링 구조·GPU 성능 문제 | `core_engineer` |
| 실제 카메라·비스듬한 시점·관련 애니메이션 포즈에서 메시 변형·재질·조명·UI·VFX 검토 | 제작자와 별도의 `visual_reviewer` |

- 메인은 원하는 스타일·참고 자료·적용 자산·완료 조건을 확인하고 담당 파일과 편집기 사용 순서를 정한다. 제작을 위한 일회성 도구 명령은 `graphics_artist`가 수행하고, 유지보수할 코드 산출물은 구현 담당에게 넘긴다.
- 같은 Blender·Unity Editor 인스턴스는 한 에이전트씩 조작한다. 제작 담당이 변경 자산·저장 상태·카메라·포즈·캡처 조건을 인계한 뒤 검토 담당이 확인하고, 보정은 제작 담당에게 돌려보낸다.
- 원본을 덮어쓰기 전 복구본을 확보하고, 요청 범위 밖의 메시·리깅·웨이트·재질·씬 연결을 보존한다. 외부 코드·에셋·공개 참고 자료는 [재사용 규칙](reuse.md), Unity 표현 수치와 인스펙터는 [Unity 설정 규칙](unity.md)을 따른다.
- 화면 근거로 확인한 결과와 추정을 구분한다. 메시 통계·컴파일·임포트 성공만으로 시각 검증을 통과했다고 보고하지 않으며, GPU 성능 개선은 같은 조건의 측정으로 확인한다.

## 의사결정 패널 역할 배정

실행 순서와 평가 형식은 [의사결정 패널 스킬](../../.agents/skills/decision-panel/SKILL.md)을 따른다.

- 독립 제안은 안건을 이해할 수 있는 담당 역할로 3명을 배정한다. 같은 역할을 여러 명 호출할 수 있으며, 관점이 다른 역할을 섞을 때도 목표와 제약은 동일하게 전달한다.
- 평가는 사용자가 지정한 분야와 안건에 영향받는 분야마다 별도 담당을 배정한다. 개발은 구현 범위에 따라 `implementer` 또는 `core_engineer`, 그래픽은 제작 검토에 `graphics_artist` 또는 실제 화면 검토에 `visual_reviewer`, 게임 기획은 위 기획 분야별 배정 기준을 사용한다. 마케팅처럼 등록된 역할이 없는 분야는 기본 서브에이전트에 담당 관점과 평가 기준을 지정한다.
- 평가자 총수에 별도 상한을 두지 않는다. 한 분야에서도 서로 다른 전문 쟁점이 있으면 담당을 추가하고 평가 기준을 구분한다. 아래 동시 실행 규칙의 슬롯 수에 맞춰 평가를 나누고, 남은 담당을 이어서 호출한다. 제안 3건은 서로 독립적이므로 가용 슬롯이 있으면 함께 진행할 수 있다.
- 종합과 개선은 제안자·평가자와 별도로 호출한 `specialist`가 맡는다.

## 위임과 병렬 실행

- 기본 동시 실행은 서브에이전트 2개다. 독립성이 분명하고 이점이 있는 작업은 이유를 정하고 3개까지 실행한다. 설정의 상한은 메인을 제외한 3개다.
- 각 작업에 확인된 요구, 담당 파일·자산, 관련 규칙, 완료 조건과 검증 방법을 전달한다. 같은 대화 전체를 반복 전달하기보다 필요한 근거를 선별한다.
- 현재 세션에서 역할을 직접 선택할 수 있으면 해당 역할을 지정한다. 역할 선택 기능이나 해당 역할이 노출되지 않으면 역할 파일의 모델·추론 수준을 모두 명시하고 담당 지침을 전달한다. 모델을 직접 지정할 때 대화 상속을 끄는 도구에서는 `fork_turns="none"`을 사용한다.
- 파일별 수정 담당자를 정한다. 같은 Blender·Unity Editor 인스턴스와 연결된 자산·씬·프리팹·인스펙터는 한 에이전트씩 순서대로 조작한다. 관련 구현이 끝난 뒤 같은 상태를 기준으로 빌드·테스트·리뷰를 수행한다.
- 조사·시각 검토·검증·리뷰·고난도 분석은 소스 수정 없이 근거를 보고하는 역할이다. 검증 로그와 승인된 캡처는 지정 산출물 경로에 기록한다. 실제 도구 권한은 부모 세션에서 상속한다.
- 중요한 변경은 구현과 리뷰 담당을 분리한다. 실패나 불확실성이 커지면 재현 결과와 확인한 근거를 메인에 전달하고 `core_engineer` 또는 `specialist`로 넘긴다.
- `xhigh`·`max`는 특히 어려운 분석에 선택적으로 사용하고 상향 이유를 기록한다. 사용자 의도가 불명확하면 메인이 재질문한 뒤 관련 구현을 진행한다.

운영 기준은 2026-11-05에 합의했고 2026-11-06에 게임 기획 역할을 추가했다. 모델별 실측 결과를 바탕으로 이후 조정할 수 있다. 설정 형식은 공식 문서를 따른다. [Codex 서브에이전트 문서](https://learn.chatgpt.com/docs/agent-configuration/subagents)
