# 무료 GitHub·Unity 에셋 조사와 활용

## 구현 전 조사

- 새 기능이나 도구를 구현하기 전에 기존 프로젝트 코드·설치 패키지를 확인하고, 무료 GitHub 프로젝트와 Unity Asset Store·Unity 공식 무료 샘플에서 활용할 자료를 웹으로 조사한다. 같은 기능을 직접 다시 만드는 비용을 줄이는 것을 기본 방침으로 한다.
- 기능 전체를 대신하는 패키지뿐 아니라 필요한 알고리즘, Editor 도구, VFX·셰이더·사운드·UI 에셋도 검토한다. 이 프로젝트의 모델 없는 표현 방식과 서버 권위 구조를 지킨다.
- 기능과 관련된 후보만 확인한다. 이미 확인한 후보는 조사 기록을 재사용하고 도입 시 버전·가격·라이선스 등 바뀔 수 있는 사항을 다시 확인한다. 단순 오타·수치 수정처럼 재사용 조사로 이득이 없는 작업은 생략할 수 있다.

## 채택 기준

- 원본 저장소·공식 배포 페이지·라이선스에서 무료 여부, 상업적 이용, 수정·배포 조건, 표시 의무와 포함된 제3자 자료의 조건을 확인한다. 공개 저장소이거나 무료로 다운로드된다는 이유만으로 사용 가능하다고 판단하지 않는다. 불명확하면 복사·도입하지 않는다.
- Unity 6000.6.0f1·URP, .NET 10, 공유 코드의 netstandard2.1·C# 9, 대상 플랫폼 중 실제 적용 위치에 필요한 호환성을 확인한다. 서버 전용 코드를 Unity나 `shared/`로 가져오지 않는다.
- 최근 릴리스·변경 내역·주요 이슈·문서·유지보수 상태를 확인한다. 오래된 코드라는 이유만으로 탈락시키지는 않으며, 해당 기능의 안정성과 수정 부담을 함께 판단한다.
- 도입·연결·수정·검증·업데이트 비용을 직접 구현 비용과 비교한다. 요구를 충족하고 전체 작업을 줄이는 자료는 우선 활용하되, 작은 기능을 위해 큰 프레임워크나 중복 패키지를 들이지 않는다.

## 도입과 검증

- 사용자가 요청한 기능 범위에서 위 기준을 통과한 무료 자료의 활용은 이 지침으로 허용한다. 이미 허용된 범위의 도입에 같은 확인을 반복하지 않는다. 유료 구매·구독, 추가 비용이 생기는 서비스, 기존 기술 스택의 교체나 라이선스 조건에 대한 별도 결정은 구체적인 대상과 영향을 설명하고 확인받는다.
- 필요한 부분만 가져오고 버전·태그·커밋을 고정한다. 원본 코드·에셋의 출처와 라이선스를 보존하고 필수 의존성도 확인한다. Unity 패키지는 Package Manager로 연결하며, 라이선스가 허용하는 범위에서 프로젝트에 필요한 파일만 포함한다.
- 외부 원본은 직접 수정하기보다 프로젝트 코드에서 연결한다. 수정이 불가피하면 변경 위치·이유·기준 버전을 기록해 이후 업데이트 시 비교할 수 있게 한다.
- 실제 적용 범위에 맞게 빌드·테스트·Editor 컴파일을 확인하고, VFX·셰이더 등 표현 에셋은 해당 카메라에서 시각 검증한다. 성능상 이점을 내세우면 측정한다. 실행하지 못한 검증과 한계는 보고한다.

## 기록

- 조사 결과는 해당 작업 문서에 원본 링크, 확인일, 채택 여부와 이유를 짧게 남긴다. 적합한 후보가 없으면 조사 범위와 직접 구현 이유를 한 줄로 적는다. 조사하지 않은 자료를 확인했다고 보고하지 않는다.
- 실제 도입 시 `Docs/third-party.md`를 생성하거나 갱신해 자료명·원본 URL·고정 버전/커밋·라이선스/고지 위치·사용 경로·수정 사항·검증 결과를 기록한다. 긴 후보 목록을 루트 `AGENTS.md`에 추가하지 않는다.
