# GitHub·Unity 에셋과 공개 자료 조사·활용

## 구현 전 조사

- 새 기능·도구·그래픽 작업 전에 기존 프로젝트 코드·설치 패키지를 확인하고, 무료 GitHub 프로젝트와 Unity Asset Store·Unity 공식 무료 샘플을 우선 조사한다. 유료 제품의 공개 이미지·YouTube 시연·공식 문서도 허용되는 범위에서 참고 후보로 조사한다. 같은 기능을 직접 다시 만드는 비용을 줄이는 것을 기본 방침으로 한다.
- 기능 전체를 대신하는 패키지뿐 아니라 필요한 알고리즘, Editor 도구, VFX·셰이더·사운드·UI 에셋도 검토한다. 이 프로젝트의 모델 없는 표현 방식과 서버 권위 구조를 지킨다.
- 기능과 관련된 후보만 확인한다. 이미 확인한 후보는 조사 기록을 재사용하고 도입 시 버전·가격·라이선스 등 바뀔 수 있는 사항을 다시 확인한다. 단순 오타·수치 수정처럼 재사용 조사로 이득이 없는 작업은 생략할 수 있다.

## 채택 기준

- 후보의 기능·구조·의존성·성능·보안·프로젝트 적합성을 분석하고, 원본 도입·부분 재사용·참고 후 독자 구현·대체재 중 작업을 줄이는 방식을 선택한다. 검색 결과만 보고 무분별하게 가져오지 않는다.
- 원본 저장소·공식 배포 페이지·라이선스에서 가격과 상업적 이용 권한을 구분하고, 수정·배포·표시 의무와 포함된 제3자 자료의 조건을 확인한다. 무료·공개라는 이유만으로 사용 가능하다고 판단하지 않는다. 라이선스가 없는 공개 저장소도 재사용 허용으로 보지 않으며, 권한이 불명확한 원본은 복사·도입하지 않는다. [GitHub 공식 안내](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)
- Unity 6000.6.0f1·URP, .NET 10, 공유 코드의 netstandard2.1·C# 9, 대상 플랫폼 중 실제 적용 위치에 필요한 호환성을 확인한다. 서버 전용 코드를 Unity나 `shared/`로 가져오지 않는다.
- 최근 릴리스·변경 내역·주요 이슈·문서·유지보수 상태를 확인한다. 오래된 코드라는 이유만으로 탈락시키지는 않으며, 해당 기능의 안정성과 수정 부담을 함께 판단한다.
- 도입·연결·수정·검증·업데이트 비용을 직접 구현 비용과 비교한다. 요구를 충족하고 전체 작업을 줄이는 자료는 우선 활용하되, 작은 기능을 위해 큰 프레임워크나 중복 패키지를 들이지 않는다.

## 유료·이용 제한 자료의 활용

- 유료 자료도 이미 보유했거나 사용자가 도입을 승인한 유효한 라이선스로 상업적 이용·수정·팀 사용 조건을 충족하면 활용한다. 가격만으로 채택하거나 제외하지 않는다.
- 권리자가 공개한 이미지·YouTube 시연·문서에서 일반적인 기능·동작 원리·연출 기법을 분석하고, 이용 조건이 허용하면 이를 기능 명세로 정리해 독자 구현한다. 원본 코드·모델·텍스처·음원·영상 프레임을 가져오는 작업에는 별도의 재사용 권한을 확인한다.
- 공개 열람 가능 여부와 다운로드·스크래핑·AI 도구 입력·생성 참고의 허용 범위를 구분한다. Unity Asset Store 등 제공처가 AI 입력이나 제작 과정에서의 이용을 제한하면 그 자료를 해당 방식으로 사용하지 않고, 허용된 설명·자료나 대체재를 찾는다. [Unity 약관](https://unity.com/legal/as-terms)
- 상업 이용 불가·수정 불가·라이선스 부재가 확인돼도 검토를 바로 끝내지 않는다. 추가 이용허락, 상업용·듀얼 라이선스, 상업 이용 가능한 대체재, 보호되는 표현을 복제하지 않는 독자 구현이 가능한지 조사하고, 확인된 방법을 작업 범위에서 활용한다.
- 이름·파일명·변수명 변경, 주석 삭제, 코드 일부 수정만으로 저작권이나 기존 라이선스 의무가 사라진다고 판단하지 않는다. 이런 변형이나 고지 제거를 권리 제한의 우회 근거로 삼지 않는다. 허용된 수정은 해당 조건과 고지를 지켜 진행한다. [저작권법 제22조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1033063637), [미 저작권청 FAQ](https://www.copyright.gov/help/faq/faq-fairuse.html)
- 독자 구현은 원본을 단순 변형하는 대신 분석한 기능 명세와 허용된 일반 원리에서 새 코드·자산을 작성한다. 필요한 경우 관련 특허·상표·계약 조건도 확인하며, 독자 구현이라는 명칭만으로 이용 가능하다고 확정하지 않는다. 권한이 불명확한 부분은 도입하지 않고 확인된 대체안으로 작업을 계속한다.

## 도입과 검증

- 사용자가 요청한 범위에서 위 기준을 통과한 무료 자료, 이미 사용 권한을 확보한 자료, 허용된 공개 자료의 분석과 독자 구현은 이 지침으로 허용한다. 이미 허용된 범위의 활용에 같은 확인을 반복하지 않는다. 새 유료 구매·구독, 추가 비용이 생기는 서비스, 기존 기술 스택의 교체나 프로젝트 코드 공개처럼 배포 조건을 바꾸는 라이선스 의무는 구체적인 대상과 영향을 설명하고 확인받는다.
- 필요한 부분만 가져오고 버전·태그·커밋을 고정한다. 원본 코드·에셋의 출처와 라이선스를 보존하고 필수 의존성도 확인한다. Unity 패키지는 Package Manager로 연결하며, 라이선스가 허용하는 범위에서 프로젝트에 필요한 파일만 포함한다.
- 외부 원본은 직접 수정하기보다 프로젝트 코드에서 연결한다. 수정이 불가피하면 변경 위치·이유·기준 버전을 기록해 이후 업데이트 시 비교할 수 있게 한다.
- 실제 적용 범위에 맞게 빌드·테스트·Editor 컴파일을 확인하고, VFX·셰이더 등 표현 에셋은 해당 카메라에서 시각 검증한다. 성능상 이점을 내세우면 측정한다. 실행하지 못한 검증과 한계는 보고한다.

## 기록

- 조사 결과는 해당 작업 문서에 원본 링크·확인일, 분석한 기능, 이용 조건과 판단 근거, 원본 도입·부분 재사용·참고 후 독자 구현·대체재 중 선택과 이유를 짧게 남긴다. 영상은 실제 확인한 구간과 관찰·추정을 구분한다. 적합한 후보가 없으면 조사 범위와 직접 구현 이유를 한 줄로 적는다. 조사하지 않은 자료를 확인했다고 보고하지 않는다.
- 실제 도입 시 `Docs/third-party.md`를 생성하거나 갱신해 자료명·원본 URL·고정 버전/커밋·라이선스/고지 위치·사용 경로·수정 사항·검증 결과를 기록한다. 긴 후보 목록을 루트 `AGENTS.md`에 추가하지 않는다.

권리·약관 관련 공식 자료는 2026-11-05에 확인했다. 실제 후보를 활용할 때는 적용 법과 해당 버전의 조건을 다시 확인한다.
