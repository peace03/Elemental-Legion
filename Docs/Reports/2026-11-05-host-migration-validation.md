# 인터넷 방 자동 서버 승계 구현·검증

2026-11-05. 인터넷 플레이어 방의 대기실과 전장을 대상으로 한다. 일반 UDP와 중계 판정 방의 기존 입장 경로는 유지한다. 프로토콜은 v14이며 클라이언트·동봉 서버·중계를 함께 갱신해야 한다.

**후속 확인:** 아래에 남겼던 EditMode 2개 실패와 Editor Undo 크래시는 [후속 수정·검증](2026-11-05-editor-undo-fix.md)에서 해결했다. 전체 EditMode 25/25를 3회 연속 통과했고 동일 Editor가 유지됐다. 아래 17/19와 크래시 기록은 당시 원본 결과로 보존한다.

## 구현

- 공유 시뮬레이션은 디스크 복원과 별도로 승계 상태를 캡처·복원한다. 틱·개체 ID·난수·전투 효과·양성 예약·건설·집결·명령 제한과 대기 명령, AI 판단 상태를 보존한다. 기존 디스크 복원의 유령 전환 규칙은 유지한다.
- 중계는 방과 현재 서버의 수명을 분리한다. 실행 가능한 사람 참가자를 입장 순으로 예열하고, 정상 퇴장은 최종 틱 백업을 확정한 뒤 이전한다. 장애는 마지막 검증 백업을 사용한다. 서버 프로세스만 종료되면 기존 방장의 게임 연결도 참가자로 남는다.
- 플레이어 WSS 연결을 유지하고 서버 쪽 연결만 교체한다. 새 세대의 시야·자기 상태·위치·유닛이 완성되면 화면을 한 번에 교체한다. 이전 예측·보간·결과를 초기화하며 이동 방향만 새 순번으로 전송한다. 경제 명령은 전환 중 막고 자동 재전송하지 않는다.
- 게임 본문 1,024B에 8B 세대 헤더를 붙인다. 전체 월드는 별도 인증 WSS에만 전달하며, 선택한 후보·방·세대를 검증한다. 청크 32KiB, 압축본 8MiB, 해제 후 32MiB 제한과 SHA-256을 적용한다. 손상된 백업은 검증된 정상본을 덮어쓰지 않는다.
- 업로드 연결과 예열·최종 복원 다운로드 연결을 재사용한다. 다운로드마다 일회용 복원 권한을 다시 소비한다. 최종 전환 뒤 복원 참가자에게 완성 기준 상태를 즉시 전송한다.
- 마지막 사람이 나가면 AI가 남아 있어도 방·백업·입장권과 소유한 자식 프로세스를 정리한다. 계정 복귀 키와 중계 비밀값은 승계 묶음에 넣지 않는다.

JSON `server.hostMigration`에 백업 1초, 하트비트 0.5초, 장애 감지 3초, 후보 준비·복원 5초, 전체 복구 10초, 알림 지연 1초를 추가하고 임시 경로에 등록했다. 게임 밸런스는 이번 승계 작업에서 조정하지 않았다.

## 자동 검증 범위

공유 규칙 테스트는 같은 입력으로 원본·복원 월드의 상태·사건·난수와 AI를 비교하고, 대기 명령의 한 번 실행과 기존 디스크 복원을 확인한다. 실제 TLS 통합 테스트는 대기실·전장의 정상/강제 승계, 연속 인계, 후보 실패, 이전 세대 명령, 방 비밀번호, 백업 권한과 마지막 사람 퇴장을 확인한다.

회귀 테스트로 긴 대기실 후 시작 시의 잘못된 장애 감지, 백업 이후 참가한 새 방장, 복원 bridge 도착 순서, 현재 사람과 이전 AI의 정원 경합, 아직 연결되지 않은 참가자 슬롯 보존을 재현해 수정했다. 시야의 표시 해제와 방장 패배는 완성 기준 상태와 인계 완료를 기다리도록 검증한다.

빠른 15인 입장에서는 매 대기실 갱신마다 같은 실행 가능 알림을 보내 명령 제한을 소진하는 문제도 재현했다. 같은 세대·같은 값은 한 번만 알리며, 값이나 세대가 바뀌거나 새 연결을 시작할 때 다시 알린다. 입력 제한은 높이지 않았다. 마지막 사람 퇴장과 겹친 예비 서버 시작은 인증된 정상 종료나 `retire`만 정상 정리로 처리하고, 인증 거절과 잘못된 준비 응답은 계속 실패시킨다.

후보의 실제 월드 구성은 권한 전환 전에 끝낸다. 세대 확정 직후 후보가 실패하는 회귀에서는 세대 2에서 다음 후보의 세대 3으로 복구하고, 이전 서버 재개와 잘못된 정상화 알림을 차단했다. 전환 완료는 초대 송신뿐 아니라 남은 참가자의 새 bridge 연결까지 기다린다. 후보 준비부터 연결까지 5초, 전체 재시도 10초 예산을 적용하며, 호출자 취소를 참가자의 소켓 고장으로 취급하지 않는다.

마지막 EditMode 완료 JSON을 기록한 뒤 Unity Editor의 네이티브 크래시 로그가 남고 Editor 연결이 종료됐다. 컴파일 오류가 없다는 결과와 17/19 테스트 완료는 확인했지만 크래시 원인·재시작 후 안정성·Player 시각 동작은 확인하지 않았다. 전체 EditMode 통과나 Unity 런타임 검증 완료로 보고하지 않는다. 최종 통계 회귀에서 증분 출력 DLL이 수정 전 결과를 내던 경우는 전체 재빌드로 해소하고 307개를 다시 통과시켰다.

## 실제 15인 측정

실제 `ClientConnection` 15개와 독립된 방 서버 프로세스를 사용한다. 정상 퇴장 봇은 같은 계정으로 복귀하고 다음 회차를 다시 15명에서 시작한다. Release, 20Hz, 시드 1, 워밍업 30초, 회차 사이 총 300초 진행을 사용하며 전환·복귀 시간은 별도 경과 시간에 포함한다. 일반 시작 규칙으로 진행하므로 최대 인구 750기 부하와 같다고 해석하지 않는다.

장비는 Intel Core i5-12400F, .NET SDK 10.0.401, 실행 런타임 .NET 10.0.12다. 제어 실행은 같은 Windows PC의 HTTPS/WSS 루프백이며, localhost 임시 인증서를 현재 사용자 저장소에서 신뢰하도록 한 뒤 운영체제의 기본 TLS 검증을 사용했다. 인증서 검증을 끄는 옵션은 사용하지 않았다. 정상 인계는 Release DLL 서버, 강제 종료 최종 실행은 같은 소스의 Windows x64 자체 포함 EXE를 사용한다.

### 지표의 의미

- 정상 전환 공백은 각 회차에서 가장 늦은 참가자의 전환 알림 수신→완성 기준 상태 수신을 사용한다. 서버 동결 ACK 시각을 직접 잰 값은 아니다. 마지막 정상 위치→기준 상태 공백도 함께 기록한다.
- 강제 장애는 마지막 정상 위치→완성 기준 상태를 사용한다. 백업 나이는 중계가 검증본을 받은 시각부터 확정 알림까지이며, 실제 되돌아간 틱과 구분한다.
- 틱 시간은 봇 판단·시뮬레이션·복제·전송 큐 등록·틱 경계 백업 복사까지 포함한다. 직렬화·압축·WSS 전송은 틱 밖에서 따로 측정한다. 할당은 해당 틱 스레드와 압축 작업 스레드의 실제 할당량이다.
- 추가 대역폭은 중계가 확인한 압축 백업 본문 기준이다. TLS·TCP·WSS 헤더와 재전송은 포함하지 않는다. 세대별 파일 안의 틱 누락·역행, 관측하지 않은 호스트 파일과 요청하지 않은 세대 변경은 실패로 기록한다.

### 초기 공개 터널 실행

같은 Windows PC에서 Cloudflare 공개 터널을 경유했다. 다른 집의 PC나 제어된 지연 환경을 사용한 결과는 아니다. 정상 인계 10회에서 남은 참가자 연결과 자산은 유지했으나 전환 공백 p95는 1,047.05ms, 마지막 위치 기준 p95는 1,092.54ms로 500ms 목표를 넘었다. 백업 포함 틱 p99는 13.09ms, 최대 36.47ms, 50ms 초과 0회였다. 실제 부하는 플레이어 원소 41~54기, 중립 최대 1,331기, 측정 공격 1,853회였다.

이 실행에는 시작 직후 요청하지 않은 세대 변경이 있어 전체 통과로 판정하지 않는다. 긴 대기실의 진행 시계가 전장으로 이어지던 문제를 테스트로 재현해 수정했다. 이후 공개 터널 강제 종료 실행에서도 반복 중 예기치 않은 세대 변경이 발생하여 진단과 재측정을 진행했다. 실패 결과도 보존하며 성공 결과로 합산하지 않는다.

## 운영과 남은 확인

5번 런처는 최신 중계를 빌드하고, Windows Player 빌드 과정은 같은 최신 자체 포함 서버를 게임에 묶는다. 게스트에게도 서버가 포함되어야 예비 후보가 될 수 있다. 상시 중계의 HTTPS 설정·서비스 주소 교체·입장 확인 순서는 [README](../../README.md#온라인-서버-운영)에 있다. 중계가 종료되면 해당 중계의 방은 종료되며, 종료한 방을 다른 중계에서 이어 하지는 않는다.

Linux 배포 환경이 없어 방향별 40ms ±10ms·1% 유실 NetEm 조건은 수행하지 않았다. 다른 네트워크의 Windows Player 두 대에서 실제 창 닫기·전원 종료·알림과 조작 체감도 확인하지 않았다. 이 항목은 로컬 TLS 봇 성공으로 대체하지 않는다. PC 전원 종료 시험은 중계와 참가자를 분리한 환경에서 해야 한다.

승계 진단을 켜면 `.snapshot.br`에 전체 월드가 남는다. 이 파일은 테스트 전용 비공개 경로에 보관하고 공개 보고서에 첨부하지 않는다. 자동 테스트의 임시 localhost 인증서와 이번 요청이 실행한 측정용 프로세스는 종료 후 제거한다.
