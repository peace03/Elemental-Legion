# 메인 월드 전환과 검증 판단

승인된 [구현 계획](../Plans/2026-11-09-main-world-improvement.md)의 작업14 기록이다. 구현과 자동 검사를 개발 저장 경로에서 진행했으며 운영 저장 변환·서비스 전환은 수행하지 않았다. 세부 기능과 단계별 근거는 [구현 기록](2026-11-09-main-world-implementation.md)을 따른다.

## 자동 검사와 실제 조작의 구분

- 실제 UDP `ClientConnection`으로 익명·계정 입장, 동시 계정 거절, 유령 복귀, 구 대기 명령 제거와 새 세션 순번을 검사했다. 시작 무료 원소·본진·시설 ID·잔고·귀환 대기를 유지하며 새 계정과 만료 후 입장을 구분한다. 재접속으로 신규 보호를 재지급하지 않는다.
- 2/4/8/15인 방에서 사람과 AI를 섞은 배치·로그아웃·복귀·복원을 검사했다. 이 검사는 방 규칙의 시뮬레이션과 저장 경로이며 같은 수의 Windows Player를 조작한 결과는 아니다.
- 1,680m 양끝의 자기100기, 정상 재편·분대 시야 전환·귀환 전후를 UDP 형식과 WSS 세대 헤더로 왕복했다. 축별 양자화 오차는 `1680/(2×32767)`에 수치 오차를 더한 범위로 검사한다. 이는 실제 외부망 전송 시험과 구분한다.
- 실제 `OnlinePeer.Run` 송신 루프에 제어 가능한 소켓을 연결해1MiB 포화, 신뢰 순서, 최신 위치 교체, 전송 중 지연과 종료 정리를 검사했다. 기존4096개 분할·역순·누락·중복·2초 제한·수신 원자성 검사도 유지한다.
- 보관된 일반/M5 데모 월드와 백업4개는 지원 v1 JSON과 해시가 달라 변환을 거절했다. 원본과 테스트 복사본 해시 보존을 확인했으며 정상 운영 이관으로 세지 않았다. 운영 저장의 해시가 맞지 않으면 서버가 시작을 거절하고 원본을 덮어쓰지 않는다.

근거 경로는 `.artifacts/main-world-trial` 아래다. Blender의 CPU 경합이 관측됐고 기본 병렬 검사에서도 네트워크 대기가 실패했다. 원인을 CPU 하나로 단정하지 않았으며, 기존5/8/10초 제한·인증서 검증·규칙 assert를 바꾸지 않고 직렬 실행으로 분리했다. 직렬 옵션의 실제 적용은 `task14/serial-test-adapter.log`에서 확인했다. 외부 부하가 없는 환경에서 기본 병렬 전체 검사를 다시 통과했다고 주장하지 않는다.

```powershell
dotnet build server/ElementalLegion.sln --no-restore -m:1 -nodeReuse:false
dotnet test server/ElementalLegion.sln --no-build --no-restore -m:1 -nodeReuse:false -- xUnit.ParallelizeTestCollections=false
```

## 성능 검증 보류

2026-11-09 사용자가 **현재는 기능 검증까지만 마무리**하도록 선택했다. 최종 코드의1000틱 준비·10000틱 측정, 장기 방어/회복,15인 네트워크 대역폭과10ms/50ms 통과 판정은 미확정이다. 측정 도구와 임계값 판정은 구현·자동 검사했다.

초기 수정 전 분산10000표본 p99는76.282ms였다. 중간100표본 예비의 분산/밀집과 최적화 후 CPU 경합 결과는 별도 로그이며 최종 통과 증거로 쓰지 않는다. 특히 고정 최대 부하는 사망 뒤 다음 표본을 재생성하므로 새 월드의 첫 틱·전체 복제 비용과 준비 할당·GC를 함께 읽어야 한다. 부하가 줄어든 연속 결과를 최대 부하 성공으로 표시하지 않는다.

## 운영 전환 조건과 복구

1. 이전 실행 패키지와 원본 JSON, 계정 폴더·월드·정상 백업을 서버가 멈춘 상태에서 함께 보관하고 각 파일의 SHA-256을 기록한다. 개발 시작 시 보관한 구형 월드·JSON·소스·해시 자료는 `.artifacts/main-world-trial/baseline-20261109`에 있다. 이것만으로 실제 운영 실행 패키지와 계정 복구 세트를 확보했다고 보지 않는다.
2. 원본 저장의 해시와 일치하는 옛 JSON을 확보한다. 현재 보관4개는 이 조건을 충족하지 못하므로 운영 전환을 보류한다. 저장의 해시만 바꾸거나 검사용 JSON을 임의로 대입하지 않는다.
3. 새 저장 루트에 계정 폴더를 별도로 보존하고, 원본 월드 파일이 직접 들어 있는 폴더에서 **아직 없는 새 월드 폴더**로 변환한다. [변환 명령](../../README.md#구형-월드-저장-변환)의4개 옵션과 `migration-report.json`을 확인한다. 원본과 새 경로를 섞어 실행하지 않는다.
4. 같은 새 실행 파일·JSON·변환한 저장 루트로 격리 서버를 연다. 계정 복귀·양성·건설·집결·전투·정상/장애 승계와 종료 후 재복원을 확인한다. 2~4인에서8인·15인으로 늘리고 일반 월드·LAN·WSS를 각각 기록한다.
5. 실제 Windows Player 두 대의 연결·조작, 외부망 접속·대역폭과 사람 플레이의 방어 대응·가독성을 확인한 뒤 전환을 결정한다. 새 형식으로 진행한 저장을 구형 서버에 넣지 않는다.
6. 실패하면 새 서버를 멈추고 **이전 실행 파일·JSON·계정/월드 저장 묶음 전체**를 복구한다. 새 진행분을 구형에 역변환하지 않으며 새 저장은 진단용 별도 경로에 보존한다.
