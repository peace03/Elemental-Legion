# M3 검증 기록 — 2026-11-03

## 상태

M3 서버·v3 복제·HUD·원소 표현·효과음·테스트 모드를 구현하고 자동 검증했다. **M3 전체 수용 완료는 보류**다. 실제 Play/Windows Player의 최종 아트·조작·두 화면 시야 분리·전체 프레임60fps는 사람이 확인해야 한다. 기존 M1 이동·보간/M2 연무의 수동 보류도 그대로다. M0 밀집10ms 미달은 승인된 별도 최적화 보류로 유지한다.

기준: Unity6000.6.0f1/URP17.6/LiteNetLib1.3.5/uGUI·TMP, .NET10.0.302 직접 호출, RTX3070Laptop/D3D11/1920×1080. `global.json`10.0.401과 gamedata SHA-256 `08fc75de1665c4ef6e940fa992610eadc0af7b593bd6472f3df47f7f2f9fd42b`을 유지했다. 새 UPM/NuGet 의존성·밸런스 변경 없음. 기존 사용자/M1/M2 작업을 보존했고 Git stage/commit/push를 하지 않았다.

## 다시 실행하는 방법 — 이 절을 그대로 사용

입력 장소는 **Windows PowerShell 또는 터미널의 PowerShell 탭**이다. 현재 작업 폴더는 무관하다.

1. 이전 서버를 실행한 터미널에서 **Ctrl+C**. v1/v2 서버가 같은 포트에 남아 있으면 v3 접속이 실패한다. Unity도 Play를 중지한다. 검증 과정에서 사용자의 기존 M2 서버를 임의로 종료하지 않았다.
2. 아래 중 하나를 실행한다. 런처가 설치된 .NET10 SDK를 찾아 **최신 소스를 매번 Release 재빌드**하고 실행한다. 고정 SDK가 없으면 이 PC의10.0.302를 직접 호출하며 global.json을 수정하지 않는다.

```powershell
# 일반: 시작3기·0핵·양성소 없음
& 'C:\project\game\Elemental-Legion\Elemental-Legion\client\Tools\Start-Server.ps1' -ReportNetwork -ReportGameplay

# 혼자 M3 루프 검증: 위 일반 서버를 Ctrl+C로 종료한 뒤 실행
& 'C:\project\game\Elemental-Legion\Elemental-Legion\client\Tools\Start-Server.ps1' -Scenario m3-demo -ReportNetwork -ReportGameplay

# 실행하지 않고 최신 소스 빌드만 확인
& 'C:\project\game\Elemental-Legion\Elemental-Legion\client\Tools\Start-Server.ps1' -BuildOnly
```

3. 서버 첫 줄의 **`M3 UDP 서버: protocol=3; scenario=normal` 또는 `scenario=m3-demo`** 확인. 예전 `Temp/M2Work` DLL 명령은 사용하지 않는다. 런처 출력은 `client/Temp/ServerRun/dotnet-artifacts`로 분리했다. 실행 중인 같은 출력 DLL을 다시 빌드하려면 해당 서버를 먼저 Ctrl+C로 종료한다.
4. Unity 컴파일이 끝난 뒤 `Assets/_Project/Scenes/Legion.unity`에서 사람이 Play → `127.0.0.1` → **물** → 접속. 이미 접속 중이면 연결 종료 후 재접속한다. WASD/방향키 이동,14종 양성 버튼, **G/집결 버튼**, Master/SFX/UI 음량·음소거를 사용한다.
5. 데모 동선: 중립 접근·자동 교전 → 전향 또는 핵 드롭·자동 습득 → 본진에서 떨어져 양성 → 수비대 대기 → G 집결 → 본진 근처 자동 합류. 데모는 시드1, 두 양성소와 에너지 양성소 최초 해금 레벨,14종을 각 한 번 양성하는 실제 비용 합이다. 일반/이미 전향된 화염 중립을 구분하며 확률·전투 수치를 변경하지 않았다. 초기화는 서버 재시작이다.

실행 검증: 런처의 실제 locked restore/Release build 오류·경고0. 독립 리뷰에서 `--scenario normal`을 parser가 거절하는 문제를 발견했다. 정상/중복/listen 누락을 RED로 재현한 뒤 normal/m3-demo와 명시적 중복 검사를 수정했고 전체148개 테스트를 통과했다.

## 구현 계약

- UnitView에 관측 체력·방벽·전향·유효 상태, typed 건물/핵/영역 ID와 관측, 자기 경제·구성·수비대·양성 진행을 연결했다. 상대 경제는 포함하지 않는다. 건물에 없는 체력·파괴 기능은 만들지 않았다.
- 매20Hz 사건을10Hz 전송 전에 보존한다. 주 공격, 실제 회복/흡혈·방벽, 추가/지속 피해 Impact, 전향/사망·핵 결과를 서버에서 확정한다. 같은 틱의 Death→Converted는 하나의 결과다. 추가 피해는 같은 틱 피격자별 합이며 원인이 섞이면 출처를 비운다.
- v3,1024B,4096유닛/최대100청크, 채널0 제어/1 시야/2 게임 결과. 모든 조각 검증·원자 적용, 미래 fog revision 대기, 신뢰 결과 전부 보존, typed ID-only Forget, 늦은 소유자/사망 복원 차단, 새 연결 초기화. 신뢰 대기2초/1MiB 또는 무결성 위반 시 명시적으로 연결을 종료한다.
- 전송 시 현재의 정확한 원 시야를 다시 확인한다. 숨은 출처 ID·소유자·원소·시작점을 제거한다. 지형 탐색 격자로 유닛·사건 권한을 넓히지 않는다.
- Move/Train/Rally는 단일 sequence·제한을 공유하고 예측에는 이동만 재적용한다. 관측 건물의 서버 위치·반경과 공유 선분–원 계산을 사용한다. 기본 개발 격자는 숨긴다.
-14종 프로필·자연 질감/굴절·몸체 배치 렌더링·이동 흔적·피격/상태·관측 체력·방벽·소멸,6반응, 공통 강착 전향을 연결했다. 일회 VFX256/보조입자32768/음성32를 노출하며 과밀 시 장식을 줄인다. 중요 결과는 계속 반영하고 전향·소멸 입자는 합칠 수 있다. 카메라 지정과 렌더 콜백으로 세션별 메시·입자를 구분한다. 시야 이탈·종료 시 관련 효과·음향을 정리한다.
- 게임플레이 집계는 도메인 누적 양성/전향이며 초기 유닛 제외, 분모0=N/A, 목표60%는 비교만 한다. 종료 요약은 틱 밖에서 출력한다.

## Windows Player 빌드

검증 복사본에서 Win64 Development Player **Succeeded/오류0/경고3**,198900591B를 빌드했다. [빌드 JSON](M3/windows-build.json)과 [종료 로그 발췌](M3/windows-build-notes.txt)를 따른다. TMP 공급자 셰이더의 deprecated `enable_d3d11_debug_symbols` 경고를 확인했고 원본 외부 자산을 임의 수정하지 않았다. ElementBody는 D3D11/D3D12 각각 인스턴싱 포함2개 변형을 유지한 빌드 로그를 확인했다. Legion과 갤러리 씬·셰이더를 포함했으며 실제 Player는 실행하지 않았다.

종료 로그에 Unity JobTempAlloc/스택 할당자 잔여 경고도 있으며 원인·Player 영향은 미확인이다. 빌드 성공이나 컴포넌트 해제 assertion을 엔진 전체의 무누수 인증으로 해석하지 않는다.

서버를 v3로 켠 뒤 사람이 다음을 실행하면 D3D11/1080p 조건을 맞출 수 있다.

```powershell
& 'C:\project\game\Elemental-Legion\Elemental-Legion\client\Temp\M3Work\WindowsPlayer\ElementalLegion.exe' -force-d3d11 -screen-width 1920 -screen-height 1080 -screen-fullscreen 0
```

`Temp` 검증 출력을 삭제하면 이 실행 파일도 사라지므로 확인 기간에는 보존한다. 빌드/클라이언트 실행과 서버 실행은 별개다. 기본 그래픽 API 순서는 원본 프로젝트 설정을 유지했고 이 명령에서 D3D11을 명시한다.

## 이동 막힘과 사람이 확인할 항목

보고된 원본 이미지의 실제 월드 좌표는 없어 같은 위치 재현은 보류다. 서버 건물 충돌은 유지했다. 본진·양성소를 실제 좌표·반경으로 표시하고, 관측한 건물만 공유 계산으로 중심 예측한다. 테스트는 중심(50,50)/반경6m에서 x43.9→진입 시 x44 접촉 전 정지, 내부에서 바깥 이동, 오래된 서버 위치/표시 복원을 확인했다. 이것은 원본 막힘의 인간 수용 완료를 뜻하지 않는다.

- Play/Windows Player에서 물·불·번개와 나머지14종/6반응의 최종 질감·상태·전향·소멸·음향을 확인한다.
- 양성14버튼·비용/시간/잠금/실패, 수비대 대기·G집결·본진 합류, 핵 습득을 실제 조작한다.
- 두 화면의 전투·시야·음향 분리, 이동 중 연무 경계·파티클 합성·Overlay UI를 확인한다.
- 원본 이동 막힘을 좌표와 본진 경계에 대조하고 가시화/예측 보완의 수용을 확인한다.
- D3D11/1080p에서 앱 전체 CPU/GPU·GC·풀과 p95≤16.67ms/60fps를 Player에서 확인한다. 미달이면 실제 값을 기록하며 밸런스로 보정하지 않는다.

건설·기지 업그레이드·본진 파괴·정규 중립/재생성·유령·저장/계정 복원·미니맵·카메라 드래그·귀환·대시·BGM은 이번에 추가하지 않았다.
