# M4 구현과 검증

일반 서버에서 중립 사냥과 핵 수집, 자유 건설과 업그레이드, 공성, 유령 기지를 실행한다. M4 데모는 같은 규칙에 초기 핵만 더한다. 기존 M3 데모는 사전 배치 양성소로 양성과 전향을 확인하는 데 사용한다.

## 검증 범위

- .NET Release 빌드 경고·오류 0개, 전체 테스트 197개가 통과했다.
- 서버 규칙은 건설 비용·해금·슬롯과 경계, 포집기 경쟁, 근접 원소의 건물 표면 공격, 타워 막타, 자기권 피해 이월, 양성소 파괴와 예약 해제, 동시 패배, 유령 공성·만료를 테스트한다.
- 생태 테스트는 일반 서버의 3기·0핵 시작부터 맵 핵 수집, 자연 양성소 건설, 양성·집결까지 진행한다. 중립의 사망과 전향에 따른 재생성과 유령 만료 후 슬롯 재사용도 확인한다.
- 루프백 UDP 테스트는 두 클라이언트의 건설·업그레이드 결과, 숨은 건물과 타워 정보 차단, 유령 관측, 본진 파괴 연결 종료와 새 입장을 확인한다.
- Unity 6000.6의 컴파일러와 프로젝트 참조로 Shared, Client, Editor, EditModeTests를 컴파일했다. Unity Play와 EditMode 실행은 수동 검증 항목이다.

## 대역폭과 부하

v5와 비교해 Gameplay 본문의 건물 레코드는 21B에서 38B로, 사건 레코드는 69B에서 71B로 늘었다. 같은 관측에서 시설 11개와 전투 사건 1건은 본문에 189B를 더한다. 추가 청크마다 29B가 더해지며 채널0의 유닛 레코드는 24B다. 이 계산은 앱 본문과 헤더 기준이다.

M4 분산 표본은 Release, .NET 10.0.12, 시드 1, 워밍업 300틱과 측정 2,000틱으로 실행했다. 15명, 플레이어 유닛 750기, 중립 147기, 건물 165개를 유지했다. 공격은 0건이고 핵 습득은 137건이었다. 서버 시뮬레이션 틱 평균 1.356ms, p99 1.589ms, 최대 2.174ms, 틱당 GC 할당 5.10B를 기록했다.

M0 회귀 측정은 Release, 시드 1, 워밍업 1,000틱과 측정 10,000틱, 초기 750기와 중립 238기로 실행했다. 본진을 잃은 봇은 이후 명령 대상에서 제외했으며, 세 시나리오를 끝까지 측정했다.

| 시나리오 | 평균 틱 | p99 | 최대 틱 | GC 할당/틱 |
| --- | ---: | ---: | ---: | ---: |
| 분산 고정부하 | 1.264ms | 1.501ms | 2.618ms | 1,277.7B |
| 밀집 고정부하 | 5.953ms | 7.314ms | 16.191ms | 9,424.0B |
| 연속 진행 | 0.307ms | 0.521ms | 5.338ms | 1,152.8B |

두 고정부하의 p99는 10ms 이하였다. 세 시나리오 모두 50ms를 넘긴 틱은 0개였다.

## Unity Play 확인

1. 기존 서버를 종료하고 [Start-Server.cmd](../../Start-Server.cmd)에서 **3. M4 데모**를 실행한다. 현재 버전은 [프로토콜 문서](../protocol.md)에서 확인하고 두 클라이언트를 `Bootstrap.unity`에서 연결한다.
2. **건설**에서 시설을 선택해 본진 주변에 배치한다. 목록과 건물의 설명, 격자와 비용, 점유·해금 거절, 우클릭·ESC 취소, 자연·에너지 타워 원소별 모델, 착공·완공 표시를 확인한다.
3. 두 화면의 미니맵에서 시작 위치를 확인한 뒤 서로 접근한다. 상대 본진의 체력과 파괴를 관측하고, 패배한 클라이언트에서 **다시 시작**으로 서버와 시작 원소를 선택한다.
4. 한 클라이언트가 일반 종료하면 다른 클라이언트가 시야 안에서 유령 표시와 만료 시간을 확인한다. **1. 일반 서버**에서는 첫 자연 양성까지 걸린 시간을 기록한다.
5. 타이틀과 현황에서 상성표를 연다. 전장에서 Tab을 누르면 내 상태와 접속 순위가 보이고, 키를 떼면 닫히는지 확인한다. 중립 무리에 접근한 뒤 물러서서 추격과 복귀를 관찰한다.
6. 타이틀에 닉네임을 입력하고 현황의 접속 순위에서 확인한다. 패배 후 다시 시작했을 때 상대가 이전 본진 근처에 있으면 다른 안전한 시작 위치를 받는지 확인한다.

2026-11-03에 [MIT Unity RTS 배치 샘플](https://github.com/manlaig/object_placement_unity)의 미리보기 흐름을 검토했다. 기존 관측소 HUD와 메시를 재사용하고, 배치 검증은 공유 서버의 원형 충돌과 명령 큐에 구현했다.

런처 PowerShell 구문 검사는 통과했다. `-BuildOnly`로 실행한 기본 런처 빌드는 기존 서버가 출력 DLL을 사용 중이어서 중단됐다. 서버 솔루션의 별도 Release 출력에서는 빌드가 통과했다.

## 피드백 반영과 프로토콜 7 검증

- .NET Release 빌드는 경고·오류 0개, 전체 테스트는 203개 통과했다. 두 UDP 클라이언트로 착공 상태, 본인만 받는 명령 결과, 시야 밖 시설 차단, 두 접속자의 합산 순위를 확인했다. Unity Shared, Client, Editor, EditModeTests 어셈블리는 컴파일을 통과했다. Unity Play와 EditMode 실행은 남아 있다.
- 임시 건설 시간은 포집기·응집로 5초, 타워 6초, 점화로 8초, 자기권 10초다. 순위 가중치는 완공 시설 10점, 본진 레벨 25점, 생존 유닛 2점, 접속 중인 상대 본진 격파 100점이다.
- 일반과 M4 데모는 km²당 18무리로 기본 맵에서 34무리가 51무리가 됐다. 중립의 감지 반경은 10m, 생성 지점 기준 추적 반경은 20m이며 군단 속도의 80%로 움직인다. 생명은 기존 회복 역할을 유지한다.
- 분산 표본은 위와 같은 시드·워밍업·표본 수를 사용했다. 15명, 플레이어 유닛 750기, 중립 221기, 건물 165개였다. 공격 0건, 핵 습득 140건으로 평균 1.331ms, p99 1.532ms, 최대 2.061ms, GC 할당 5.10B/틱이었다. 분산 표본의 값이며 밀집 추격·공성 부하는 별도다.
- v6 대비 Gameplay 본문은 자기 상태 12B, 순위 목록 4B와 접속자당 12B, 관측 건물당 8B가 늘었다. 접속자 15명과 관측 건물 11개이면 본문에 284B가 더해진다. 조각 헤더와 전송 비용은 별도다.

2026-11-03에 [uGUI 포인터 이벤트](https://docs.unity3d.com/Packages/com.unity.ugui@2.0/manual/SupportedEvents.html), [MIT RTS 배치 샘플](https://github.com/manlaig/object_placement_unity), [Reynolds의 추적 설계](https://www.red3d.com/cwr/steer/gdc99/index.html), [TrinityCore의 귀환 처리](https://github.com/TrinityCore/TrinityCore/blob/master/src/server/game/AI/CreatureAI.cpp)를 확인했다. 시설 설명은 기존 uGUI 레이캐스트, 타워는 기존 원소 프로필, 추적과 귀환은 공유 공간 격자와 원형 충돌을 활용했다.

상성 화면은 [기획서 HTML의 상성 고리](../기획서/Elemental%20Legion%20속성%20상성도.html)를 Unity에 옮겼다. 2026-11-03에 [Unity UI Extensions의 선 렌더러](https://unity-ui-extensions.github.io/ugui/controls/ui-line-renderer/)를 검토했고, 기존 uGUI에서 화살표와 원을 한 메시로 그려 화면에 연결했다. 원소 위치와 색은 게임 데이터, 피해 배율은 공유 규칙에서 읽는다.

양성 예약은 [OpenRA의 생산 대기열](https://github.com/OpenRA/OpenRA/blob/bleed/OpenRA.Mods.Common/Traits/Player/ProductionQueue.cs)의 선입선출과 선결제 흐름을 참고했다. 기존 서버 양성 명령에 프로젝트의 인구 예약·시설 파괴 규칙을 적용했다. 주력 원소는 2초 단축해 6초로 양성한다.

표시 이름은 기존 [TMP 입력 필드](https://docs.unity3d.com/Packages/com.unity.textmeshpro@3.0/api/TMPro.TMP_InputField.html)와 접속 순위를 활용한다. 시작 위치는 [OpenRA의 입장 지점 점유 검사](https://github.com/OpenRA/OpenRA/blob/bleed/OpenRA.Mods.Common/ServerTraits/LobbyCommands.cs)와 [Teeworlds의 시작 위치 평가](https://github.com/teeworlds/teeworlds/blob/master/src/game/server/gamecontroller.cpp#L943-L1021)를 검토하고, 기존 후보 배치에 거리 검증을 추가했다. 기본값은 본진 간격 300m와 상대 원소 간격 25m다. 일반 서버와 M4 데모는 km²당 24무리로 기본 맵에 68무리가 생성되며, 초기 배치와 재생성 모두 본진 건설 범위 25m 밖을 사용한다.

프로토콜 10의 Release 빌드와 전체 테스트 215개가 통과했다. 실제 루프백 UDP에서 한글 닉네임과 중복 이름의 ID 구분, 패배 후 적이 머무는 위치를 피한 새 입장을 검증했다. 서버 테스트는 중립 14종의 기본 공격, 실제 월드에서 생성된 중립 생명의 추적, 본진 건설 범위 밖 재생성을 확인한다. Unity C# 컴파일을 통과했고 Unity Play는 수동 확인 항목이다.

같은 M4 분산 측정에서 15명, 플레이어 유닛 750기, 중립 266기, 건물 165개를 유지했다. p99는 첫 실행에서 10.182ms, 반복 3회에서 4.264~5.551ms였다. 틱당 할당은 5.10B였고 공격은 0건이었다. 이 측정은 분산 시뮬레이션의 비용이며 밀집 교전과 네트워크 부하는 별도다.
