# M5 구현과 검증

일반 서버와 M5 데모는 월드 상태를 별도로 저장한다. 인터넷 방은 중앙 서버가 생성하며, LAN 방은 클라이언트에 포함한 서버 실행 파일로 연다. 대기실에서는 방장이 최소 인원과 전원 준비를 충족한 뒤 시작한다. 진행 중인 방은 참가 계정과 함께 저장하고, 살아 있는 유령의 소유자는 같은 PC의 복귀 키로 다시 입장할 수 있다. [실행 방법](../../README.md#방-만들기와-접속) · [프로토콜 v11](../protocol.md)

## 자동 검증

- .NET Release 빌드는 오류 없이 완료했고 전체 테스트 228개가 통과했다. `NU1900`은 NuGet 취약성 데이터 소스에 접근하지 못해 발생했다. 서버와 공유 프로젝트의 잠금 파일 복원은 감사 조회를 끈 별도 출력에서 확인했다. 전체 테스트는 Windows 호스트에서 실행했다. 제한된 샌드박스에서는 TLS 테스트에 필요한 Windows 인증서 키 저장소를 열 수 없었다.
- 루프백 UDP에서 LAN 방 검색, 방장 증명, 방장 승계, 준비 전 시작 거절, 전체 채팅, 같은 기지로의 복귀와 체크포인트 복원을 확인한다.
- 루프백 HTTPS/WSS에서 신뢰되지 않은 인증서와 호스트 이름 불일치, 다른 방의 입장권, 만료·재사용 입장권, 비방장·중복 시작, 시작한 방에 대한 외부 계정 입장, 분할된 1,025B 메시지를 거절한다. 테스트는 자체 생성 인증서를 사용한다. 테스트 전용 인증서 확인은 클라이언트 코드와 분리돼 있다.
- 세 플레이어의 군단을 사용해 80m 경계와 범위 밖 수신 차단을 확인한다. 시야 밖 근접 발화에는 말풍선 대상 ID가 없으며, 신고는 실제 수신자만 한 번 보낼 수 있다. WSS에서 상시 월드와 일반 방의 채팅을 분리하고 신고 기록을 확인한다.
- 저장 테스트는 계정과 월드의 연결, 중립·유령 타이머, 탐색 기록, 한 번만 적용되는 양성·건설 환불, 전투 귀속, 손상된 파일의 백업 복구와 종료한 방의 재개 차단을 확인한다. 복원한 월드의 난수는 저장한 시드와 틱으로 다시 시작한다.
- Unity 6000.6.0f1의 컴파일러와 프로젝트 참조로 Shared, Client, Editor, EditModeTests를 컴파일한다. `Start-Server.ps1`과 `Publish-LanServer.ps1`은 PowerShell 구문을 검사한다.

## 로컬 WSS 측정

Windows .NET 10.0.12 Release에서 한 방에 2명, 상시 월드에 1명이 접속한 루프백 테스트의 표본이다. 이동 명령을 전송한 뒤 적용 순번이 담긴 `Pose`를 받을 때까지 측정했다. 대역폭은 클라이언트 한 명이 받은 앱 메시지 본문이며 TLS·TCP 헤더는 제외한다.

| 항목 | 결과 |
| --- | ---: |
| 이동 명령 적용 확인 p95, 30회 | 62.739ms |
| 클라이언트 수신 | 6.45KiB/s |
| 방 스텝·복제 p99, 129표본 | 1.920ms |
| 체크포인트 메모리 복사 p99, 7표본 | 2.010ms |

저장 복사 시간은 파일 검증과 쓰기를 제외한다. 이 표는 루프백 소규모 측정이며 외부망 지연·손실과 15인 부하는 아래 공개 기준에서 확인한다.

## 설정과 재사용

M5 데모 포트 7778, LAN 검색 포트 7779, 근접 채팅 쿨타임 1초를 JSON에 추가해 `_meta.placeholderPaths`에 기록했다. 기존 근접 반경 80m, 전체 채팅 3초, 유령 600초, 저장 주기 60초를 사용한다. 온라인의 30초 입장권, 방 4개 상한, 7일 신고 보관 기간은 서비스 운영 설정이다. LAN 서버를 재시작하면 저장한 포트를 다시 사용하며, 해당 포트를 쓰는 다른 프로세스가 있으면 복원 시작을 거절한다.

2026-11-03에 Unity의 공개 방 목록 샘플을 검토했다. 샘플은 Unity 서비스에 연결하는 구조라 도입하지 않았다. 대기실 UI는 현재 관측소와 TMP를, 게임 메시지와 LAN 검색은 기존 LiteNetLib 1.3.5를 사용했다. 인터넷 연결은 .NET의 ASP.NET Core WebSocket과 `ClientWebSocket`, Windows 키 저장은 DPAPI를 사용했다. 외부 샘플 코드를 복사하거나 새 NuGet·UPM 패키지를 추가하지 않았다. [Unity 게임 로비 샘플](https://github.com/Unity-Technologies/com.unity.services.samples.game-lobby) · [ASP.NET Core WebSocket](https://learn.microsoft.com/en-us/aspnet/core/fundamentals/websockets?view=aspnetcore-10.0) · [Windows DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)

## 공개 전 확인

1. 운영자 도메인과 인증서를 준비해 비공개 HTTPS/WSS 서버를 설정한다. Windows Player에는 고정 주소와 LAN 서버 실행 파일을 포함한다.
2. 다른 공유기에 있는 Windows Player 두 대로 방 제목 검색, 준비와 시작, 전투·채팅, 같은 기지 복귀를 확인한다. LAN 검색·방 다시 열기와 한글 채팅 입력도 직접 확인한다.
3. Windows Player에서 만료·이름 불일치 인증서를 거절하는지 확인한다. RTT 80ms, 지터 20ms, 손실 1% 환경에서 명령 응답 p95 250ms 이하를 검증하고 15인 부하의 틱과 대역폭을 기록한다. 이 결과가 공개 여부를 결정한다. [M5 완료 기준](../Plans/2026-11-03-m5-online-rooms.md#완료-기준과-공개-순서)

Unity Play, Windows Player 빌드와 패키징 실행, 두 외부망 접속, 네트워크 손실·15인 부하 검증 및 공개 배포는 이번 검증에 포함되지 않았다.
