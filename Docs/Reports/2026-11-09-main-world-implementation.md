# 메인 게임 개선 구현 기록

승인된 [구현 계획](../Plans/2026-11-09-main-world-improvement.md)을 작업 순서대로 진행한다. 원본 JSON·이전 공유 소스·실제 월드 저장 4개와 해시를 `.artifacts/main-world-trial/baseline-20261109`에 보관했다. 원본 저장과 실행 중인 서버를 변경하거나 운영 이관을 실행하지 않았다.

## 기준

- 시작 커밋: `ff3f0bb1d14b942f6508be8601a694896624340d`.
- 구현 전 .NET 전체 337/337 통과. 시작 3기와 인구 20/30/40/50기를 비교 기준으로 보관했다.
- Unity 6000.6.0f1의 실제 프로젝트 경로와 Editor 연결을 확인했다. Play는 사람이 진행한다.

## 작업1 · 데이터와 저장

- 새 시험값을 JSON에서 검증하고 기본 시작 3기·기존 총 인구는 유지했다. 12기·8/4기와 확대 인구는 아직 적용하지 않았다.
- 저장 래퍼와 체크포인트 스키마를 v2로 구분했다. 디스크 재시작은 선불 양성 주문과 남은 시간을 정지·재개하고, 자발적 로그아웃은 기존 취소·환불을 유지한다. 승계에서는 정지 상태도 정확히 복원한다.
- 디스크 복귀가 명령 순번을 초기화하므로, 계획의 작업7에 있던 독립 양성 주문 ID 발급을 앞당겼다. 형식 검증과 실제 취소 권한 검증은 구분한다.
- 같은 데이터 해시가 아닌 저장과 v1 파일의 일반 로딩은 계속 거절한다. 옛 데이터의 전용 리더와 실제 v1 이관은 작업12의 범위다.
- 검증: 다음 작업의 실패 확인용 두 클래스를 제외한 .NET 전체 **378/378**, Unity 전체 EditMode **72/72** 통과. 솔루션 빌드는 경고·오류 0개다. 결과는 `.artifacts/main-world-trial/task1-regression.trx`, `task1-editmode.json`에 기록했다.

## 진행 중

작업2의 전역 인구·양성 예약과 무료 시작 자산의 보상 방지 테스트를 먼저 작성했다. 구현 전 8건 중 7건의 실패를 `task2-red.trx`에 기록했다. 구현 후에는 입장·양성·중립 재생성이 전역 예산을 공유하고, 취소·양성소 파괴·패배·유령 만료에서 예약을 한 번만 정리한다. 중립 전향으로 빈 자리가 생겼지만 예산이 부족하면 예약 없이 대기하다가 재시도한다.

신규 무료 원소와 본진의 표지를 저장·승계하며, 중립을 통한 무료 병력 수확과 유령 만료 보상도 차단했다. 일반 획득 원소와 기존 자산은 정규 출처를 유지한다. 전체 .NET 회귀는 **403/403** 통과했고 독립 리뷰에서도 수정할 결함을 찾지 못했다. 정지 중 자연 양성소가 파괴된 뒤 다른 종류의 주문이 보존되는 추가 검사도 통과했다. 결과는 `task2-regression.trx`에 기록했다.

다음 분대 입력을 위해 기존 키 설정 11개를 보존하면서 1~4, 전체 야전 5, 본진 B, 양자 이동 R의 설정 항목을 준비했다. 실제 명령 연결은 작업3 이후의 범위다.

## 구현 순서에서 조정한 사항

- 작업1에 디스크 전용 양성 정지·복귀 경로를 포함했다. DTO만 추가하면 기존 로그아웃 경로가 주문을 취소하므로 승인된 D1을 충족할 수 없다.
- 독립 주문 ID 발급과 `TrainingOrderId < Sequence` 검사 제거를 작업7에서 작업1로 앞당겼다. 실제 취소는 실행 시 소유자의 대기열을 조회한다.
- 사용자는 번호키로 분대를 선택할 때 카메라도 즉시 이동하는 방식을 선택했다. B키는 선택을 유지한 채 본진만 보여 준다.

사람 Play, Windows Player·외부망·GPU 검사와 최종 시험값 채택은 아직 진행하지 않았다. 운영 저장의 변환과 서비스 전환도 전체 검증 뒤의 별도 절차다.
