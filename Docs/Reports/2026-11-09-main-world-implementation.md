## 작업8 · 초반 경로와 자리별 공급

- 시작 군단에서 첫 핵까지 20~35m, 첫 자연 무리까지 35~70m, 첫 무리에서 다음 무리까지 70~140m인 경로를 생성한다. 공용 핵은 이웃 본진 사이에서 양쪽 접근 경로를 확인한다. 일반 월드의 1,680m·15자리·인접 336m와 중앙 에너지 구역을 유지했다.
- 초기 4핵을 공급 예산에 포함하고 가까운 곳 3묶음·공용 2묶음, 총 20핵/활성 참가자/분으로 공급한다. 자리의 크레딧·순서·첫 지급 여부·다음 틱을 저장하며 빈 자리와 유령은 적립하지 않는다. 새 계정의 같은 자리 재입장도 지급을 초기화하지 않는다.
- 생태 초기화는 기하 탐색을 마친 뒤 중립을 추가한다. 실패하면 기존 자산·예약·다음 ID·난수가 보존된다. 신규 본진은 입장 자리에 배치하고 복원은 저장된 자리 좌표를 사용한다. 구형 생태 일정의 명시적 변환은 작업12에서 연결한다.
- 전체 .NET **561/561**, 생태·저장·예약 집중 검사 **61/61**, 독립 리뷰 통과. 근거는 `.artifacts/main-world-trial/task8/task8-regression-verified.trx`다. 함께 준비한 작업9의 동일 ID 재관측 계약도 이 회귀에 포함됐다. Unity는 후보의 공유 API 연결 후 작업9와 함께 확인한다.
- 기존 임의 본진 fixture는 정규 자리로 옮겨 검증 의도를 유지했다. 새 배치에서 AI가 전향만으로 공성에 조기 진입해 성장을 멈추는 회귀를 재현했고, 실제 첫 양성 완료 뒤 공성을 우선하도록 수정했다. AI 관련20개 검사도 통과했다.
- 첫 보상20초·첫 시설90초 안팎·3/10/25분 인구를 재는 사람 플레이와 시험값 채택은 미실행이다.

## 작업9 · 확보와 구출

작업9의 코드와 자동 검증도 완료했다. 중립은 기존80% 즉시 전향을 유지하고, PvP의60% 추첨은 20초 후보와 인구 예약을 만든다. 정식 막타 분대가 5m 안에서 경합 없이60틱을 쌓으면50% 체력으로 확보한다. 구출은25% 체력·원소당1회이고, 만료 틱은 완료보다 먼저 핵으로 전환한다. 후보 위치·수명은 현재 시야, 상세 진행은 당사자의 자기 쪽에만 전달한다.

사용자가 추가로 선택한 증원 정책에 따라 피해·DOT 부여 당시 목적 분대에 귀속한다. 합류 전 증원은 권한을 지탱하지만 진행과 시너지에는 참여하지 않는다. 분대가 전멸해 소멸한 권한은 재편·새 양성·디스크/승계 복원으로 돌아오지 않는다. 실제4번 막타, 제3자 경합, 중립 비경합, 반경 이탈, 사망·소유자 제거, 마지막 예약 슬롯과 중복 확정을 검사했다.

프로토콜v20은 후보26B와 명시적 양성 대기 개수를 추가해 후보 예약을 양성으로 잘못 읽지 않는다. 종류별 Forget과 최신 권위 유닛 관측으로 같은 원소 ID의 구출·전향을 표시한다. 오래된 사망 기록은 재사용 목록으로 정리한다. 후보의 값 형식과 사전 용량 확보로 같은 밀집 첫 틱의 할당은143,624B에서9,464B로 줄었고 기존128KiB 검사 기준은 유지했다.

최종 .NET **623/623**, Unity EditMode **102/102**, 최종 공유 코드 컴파일과 독립 리뷰를 통과했다. 근거는 `.artifacts/main-world-trial/task9/task9-regression-final.trx`, `task9-editmode-final.json`, `task9-reinforcement-focused2.trx`다. 실제40대80 추격/확보 비교, 후보20초 채택과 GPU/화면 체감은 사람이 확인해야 한다.

## 구현 순서에서 조정한 사항

- 작업1에 디스크 전용 양성 정지·복귀 경로를 포함했다. DTO만 추가하면 기존 로그아웃 경로가 주문을 취소하므로 승인된 D1을 충족할 수 없다.
- 독립 주문 ID 발급과 `TrainingOrderId < Sequence` 검사 제거를 작업7에서 작업1로 앞당겼다. 실제 취소는 실행 시 소유자의 대기열을 조회한다.
- 사용자는 번호키로 분대를 선택할 때 카메라도 즉시 이동하는 방식을 선택했다. B키는 선택을 유지한 채 본진만 보여 준다.

사람 Play, Windows Player·외부망·GPU 검사와 최종 시험값 채택은 아직 진행하지 않았다. 운영 저장의 변환과 서비스 전환도 전체 검증 뒤의 별도 절차다.
