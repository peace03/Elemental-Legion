# M2 서버 시야·탐색과 3D 우주 연무 검증

2026-11-02. [승인 계획](../Plans/2026-11-02-m2.md)에 따라 구현했다. 자동 검사 결과와 사람이 수행할 완료 조건을 구분한다. M1은 사용자 Unity Play 접속 확인만 기록하고 두 클라이언트 이동·보간은 보류한다.

## 사용자 실행 절차 — 2026-11-03 추가

현재 PC에서 **Windows PowerShell**을 연다. 아래 절대 경로 명령은 어느 폴더에서 실행해도 된다. 기존 서버를 실행한 터미널에서 **Ctrl+C**로 먼저 종료한다. 같은 포트의 구버전 서버를 남겨 두지 않는다.

### 현재 검증한 M2 빌드 바로 실행

```powershell
& 'C:\Program Files\dotnet\dotnet.exe' 'C:\project\game\Elemental-Legion\Elemental-Legion\client\Temp\M2Work\dotnet-artifacts\bin\ElementalLegion.Server\release\ElementalLegion.Server.dll' --listen --report-network
```

이 경로의 DLL 존재를2026-11-03에 확인했다. M2 작업에서 별도로 만든 v2 서버다. `Temp`는 임시 폴더이므로 Unity의 정리·프로젝트 이동·새 클론 뒤 없어질 수 있고, 이후 소스 변경이 자동 반영되지 않는다. 파일이 없거나 최신 소스로 실행하려면 아래 재빌드 절차를 사용한다.

### 소스 변경 후 재빌드하고 실행

이 PC의 설치 SDK10.0.302를 직접 호출하며 저장소의 global.json10.0.401은 바꾸지 않는다. 실행 중인 서버를 Ctrl+C로 종료한 뒤 PowerShell에 아래 블록을 붙여 넣는다.

```powershell
$legionRepo = 'C:\project\game\Elemental-Legion\Elemental-Legion'
$legionDotnet = 'C:\Program Files\dotnet\dotnet.exe'
$legionSdk = 'C:\Program Files\dotnet\sdk\10.0.302\dotnet.dll'

& $legionDotnet $legionSdk restore "$legionRepo\server\ElementalLegion.sln" --locked-mode
if ($LASTEXITCODE -ne 0) { throw '패키지 복원 실패: 위 오류를 확인하세요.' }
& $legionDotnet $legionSdk build "$legionRepo\server\ElementalLegion.sln" --no-restore -c Release -m:1 -nodeReuse:false
if ($LASTEXITCODE -ne 0) { throw '빌드 실패: 기존 서버 종료 여부와 위 오류를 확인하세요.' }
& $legionDotnet "$legionRepo\server\Server\bin\Release\net10.0\ElementalLegion.Server.dll" --listen --report-network
```

기존 `server/Server/bin/Release/net10.0` 출력은 이번 재빌드가 성공해야 최신 서버가 된다. 재빌드 없이 예전 DLL을 실행해 **서버와 통신 버전이 다릅니다**가 발생한 사례를 확인했다. 현재 `Protocol.Version=2`이며 버전 검사 자체를 끄거나 번호만 맞추지 않는다. 위 재빌드 블록은 실행 중인 사용자 서버를 보존하기 위해 이번 문서 작업에서 직접 실행하지 않았다.

### Unity 접속과 종료

1. 서버 터미널의 `M2 UDP 서버` 시작 메시지를 확인하고 터미널을 켜 둔다.
2. Unity에서 `Assets/_Project/Scenes/Legion.unity`를 열고 사람이 Play를 누른다.
3. 서버 주소 `127.0.0.1`과 시작 원소를 선택하고 **접속**한다. WASD/방향키로 이동한다.
4. 버전 불일치가 계속되면 이전 서버 터미널이 남아 있는지, 위 명령의 DLL을 실행했는지 확인한다. Unity가 소스 컴파일을 마친 뒤 Play를 다시 시작한다.
5. 끝낼 때 Unity에서 연결 종료/Play 종료 후 서버 터미널에서 Ctrl+C를 누른다. `--report-network`의 종료 요약을 확인한다.

서버 재시작 시 현재 메모리 월드·탐색 기록은 초기화된다. 계정 저장·복원은 M5 범위다. 종료한 소유자 슬롯을 재사용하지 않으므로15개 새 세션 이후에도 개발 서버를 재시작해야 한다.

## 사용자 이동 막힘·표현 확인 — 2026-11-03

- 사용자는 첨부 이미지의 위치에서 **이동 입력을 해도 막힌다**고 확인했다. 첨부 이미지의 청록 사각형은 임시 아군 유닛, 작은 흰색 사각형은 군단 중심, 가는 선은 이동 확인용 LineRenderer 격자다. 격자에는 충돌 컴포넌트를 추가하지 않았다.
- 코드에서 확인한 유력 원인은 **아직 그리지 않는 본진의 서버 충돌**이다. `MovementSystem.MovePoint`는 본진 등 원형 건물과 이동 선분의 충돌을 계산한다. JSON 본진 반경은6m다. `LegionPresentation`은 유닛·중심·격자만 표시하고 본진 형상은 그리지 않는다. `MovementPrediction`도 건물 충돌을 예측하지 않아 경계에서 서버 보정이 보일 수 있다.
- 첨부 당시 월드 좌표/입력 이력은 없고 읽기 전용 확인 당시 Unity는 Play가 종료되어 있었다. 따라서 해당 이미지 위치가 본진 경계라는 런타임 확정이나 수정 완료로 기록하지 않는다. 기존 `BuildingsStopSweptMovementAndMapEdgesClamp`를 재빌드 없이 VSTest로 실행해1/1 통과했다. 건물 충돌 단위 테스트와 소스 구조를 근거로 둔 가설이다. 다음 재현에서는 막히는 위치와 서버 본진 중심의 거리를 확인한다. 우회 이동 여부도 구분한다.
- 후속 보완: 서버가 허용한 본진 위치와 충돌 범위를 화면에 연결해 보이지 않는 장애물을 설명하고, 이미 아는 건물에 대한 예측/서버 보정 체감을 검증한다. 이 조사에서는 충돌 규칙·밸런스·시야 차단을 바꾸지 않는다.
- 현재 사각 파티클은 접속·이동·시야 검증용 임시 표현이다. M3 전투 표현 통합에서 원소별 외형·이동 흔적·타격/전향/소멸 효과와 가독성을 개선한다. 최종 아트 품질을 현재 마커로 완료 처리하지 않으며, 대량 유닛에서도 성능 예산을 확인한다.

## 구현과 범위

- `VisionGrid`가 플레이어마다 현재/누적 packed 비트맵을 소유한다. JSON의168×168·10m·25m를 유지하고 지형 칸의 원/AABB 교차와 기존 유닛 원 거리 판정을 구분한다. 파일 저장·계정 복원 없음.
- 프로토콜v2, 제어채널0/시야 ReliableOrdered 채널1. 1024B 이내 기준/변경분을 revision별 검증 후 원자 적용한다. ID 전용 Forget은 즉시 숨기고 Timeline이 과거 복원을 차단한다. 미래 시야의 유닛 프레임은 최신 완성본 하나만 보관한다. 연결 종료·새 연결에서 모두 미탐색으로 초기화한다.
- `FogPresentation`은 카메라별 RG16 마스크·머티리얼·프로퍼티 블록을 소유한다. 비활성화의 자원 해제 경계를 제공한다. 전역 공유 시야 텍스처 없음. Renderer Feature 등록은 Base Game 카메라만 받고 Overlay 카메라·ScreenSpaceOverlay UI에는 적용하지 않는다.
- URP17.6 RenderGraph의 반해상도 RGBAHalf 광선 적분 → 깊이 가중 전체해상도 합성이다. 투명 월드 표현 뒤/후처리 전에 실행한다. 3D 반복 노이즈, 높이 감쇠/바람, 청록·보라, 단일 방향광/주변광과 Beer-Lambert 산란·흡수를 구현했다. 깊이 없는 배경은 월드 바닥/볼륨 AABB로 제한한다. 미탐색 셀의 점 샘플 검정 차폐가 노이즈·경계 보간 뒤에도 우선한다.
- 기본 반해상도32회/높이24m, Low 반해상도16, High 전체64. 밀도·높이·색·바람·조명·경계·품질은 인스펙터에서 조절한다. 자동 품질·다중 산란·볼륨 그림자·시간 누적은 추가하지 않았다.
- 기존 PC SSAO 등 Feature 목록을 보존하고 PC/Mobile Renderer, 기존 Legion 프리팹과 씬의 프리팹 참조를 Editor API로 연결했다. 노이즈64³ R8은 고정 시드로 생성한 공유 읽기 전용 자산이다. 기존 사용자/M1 작업·게임 JSON·패키지 잠금 파일을 보존했다.
- 플레이어별 앱 payload와 LiteNetLib Bytes/Packets, 초기/정상 송신, 평균/최대1초 KiB/s를 집계한다. `--listen --report-network`에서 접속 종료와 서버 종료에만 틱 밖에서 출력한다. 전송 통계는 LiteNetLib 헤더·재전송을 포함하며 UDP/IP 헤더를 포함한 수치가 아니다.

## 대역폭

두 실제 루프백 UDP 수신자와 같은 v2 코덱·시야 복제·통계 구현을 사용했다. 서버 승인 fixture로 일반3기/서로60m 떨어진 군단/15명 최대 인구 밀집 월드를 배치하고20Hz 시뮬레이션·Pose,10Hz Units/시야를 보냈다. 포트 임시 할당, Hello/Welcome 검증 포함. 실제 UdpGameServer의 고정 출발점 접속 검사는 별도 통합 테스트다. 15개 소켓/지연·유실 주입은 M6다.

CPU 시간으로 GPU 수치를 대체하지 않았다.

사람이 확인할 항목은 모두 보류다.

1. v1 서버를 Ctrl+C로 종료하고 새 v2 서버를 `--listen --report-network`로 실행한다. Legion 씬의 Prefab 참조와 `SpaceFog.asset` Normal을 확인한다.
2. 실제 Play와 Windows Player에서 연무의3D 깊이·바람·세 상태·이동 경계를 확인한다. 미탐색이 밝아지지 않고 파티클이 연무 뒤에서 합성되는지 본다.
3. 접속 UI와 Overlay UI의 밝기/조작, 카메라 비활성화·재활성화, 연결 종료/새 연결의 미탐색 초기화를 확인한다.
4. 두 화면의 독립된 시야·탐색, 상대 진입/이탈 즉시 표시 해제, 군단 이동/보간을 확인한다. M1 보류 항목을 같이 확인하되 완료로 선표시하지 않는다.
5. RTX3070 Laptop·D3D11의 실제1080p Player에서 같은 장면의 연무 켜기 전후 전체 GPU 프레임 비용·p95≤3ms와60fps를 측정한다. Editor 패스 표본과 별도로 기록한다.

미니맵·카메라 드래그·교전 신호·전투 연출·저장·계정 재접속은 추가하지 않았다. 새 게임 밸런스/UPM/NuGet 의존성도 없다.

## 최종 실행·리뷰 기록

독립 읽기 전용 전체 리뷰1회를 수행했다. 정상 서버 경로에서 숨겨진 유닛 좌표를 보내는 결함은 발견하지 않았다. 리뷰 이후 재리뷰를 수행했다고 주장하지 않으며 수정은 재현 검사와 전체 회귀로 검증했다.

- **Renderer 재생성 등록 수명:** 설치된 URP가 같은 Feature를 Dispose→Create하는데 카메라 등록도 함께 지우던 결함이다. 실제 RenderRequest 회귀에서 미탐색 흰 지형이 검정0 대신 밝기1.0으로 보이는 실패를 먼저 확인했다. GPU pass 자원 수명과 카메라 등록 수명을 분리했다. Presentation 종료의 명시적 등록 해제는 유지한다.
- **맵/셀 좌표 일치:** 리뷰는 현재 JSON에서 발생하지 않아 Minor로 분류했으나 유효한 mapSize1681/10에서 미탐색 지형이 열리는 영향에 따라 Important로 재분류했다. 실제 렌더에서 밝기0.578로 열린 실패를 확인한 뒤 실제 cellSize로 셀·마스크 UV를 계산하도록 수정했다. 월드 경계는 mapSize로 유지한다. 테스트 안에서만 데이터를 변형했고 원본 JSON은 바꾸지 않았다.
- 두 수정 후 .NET126/126·Unity8/8 통과, C#·셰이더 메시지0을 확인했다. 이 범위의 남겨 둔 Minor는 없다.

판단과 한계는 다음과 같다. 기존 SDK10.0.302와 별도 Release 출력으로 검증해 원래10.0.401 설정과 실행 중인 사용자 서버를 보존했다. 실행 증거 Temp 폴더는 커밋하지 않은 상태이므로 로컬에 유지하고 중요한 원본은 이 보고서의 Artifacts에 복사했다. 유효한 맵에서 미탐색을 여는 결함은 현재 JSON에서 미발생이어도 수정 대상으로 판단했다.

리뷰가 판정하지 않은 실제 Play/Windows Player의 시각·입력·카메라 콜백·두 화면 보간·UI, 전체 GPU 증가량과60fps는 보류한다. 리뷰어가 .NET/M0 측정을 독립 재실행한 것은 아니며 이 보고서는 작성자가 실행한 결과다. 밀집10ms 목표 미달과 Player 전체 프레임 GPU 목표는 완료로 표시하지 않는다. 비용은 실제 런타임 최종 수용이 아직 없다는 점이며 사람의 검증으로 남긴다.
