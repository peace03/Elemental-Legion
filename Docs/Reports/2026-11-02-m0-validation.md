# M0 구현·검증 기록

2026-11-02, 승인된 [M0 계획](../Plans/2026-11-02-m0.md)에 따라 공유 코어와 콘솔 서버를 구현했다. 실제 Unity Editor 가져오기·Play·Player 빌드는 별도 확인 항목이다.

## 구현 범위

- JSON을 한 번 검증·인덱싱하는 `GameRules`, 단일 스레드 `SimulationWorld`와 명령 접수·실행 결과의 분리.
- 이동·역할별 진형·이탈 공격·건물 선분 충돌, 정확한 거리 판정의 공간 격자.
- 14종 원소 효과·6종 시너지, 비중첩 상태 갱신·상태 유지, 피해 귀속과 부여 당시 군단 출처의 분리.
- 사망 선처리 후 전향·인구 제한·드롭 내림, 핵의 단일 습득·소멸, 양성 자원·인구 예약과 수비대 합류·집결.
- 현재 시야만 제공하는 재사용 관측 버퍼와 공용 봇, 시야 밖 사건·원인 유닛 정보의 차단.
- 환경 확인·20Hz 실행·고정부하/연속 진행 보고를 제공하는 콘솔 인수와 취소 수명.

새 패키지는 추가하지 않았다. 테스트가 콘솔 통계·시나리오도 검증하도록 서버 프로젝트 참조와 잠금 파일의 프로젝트 간 연결만 추가했으며, 기존 외부 패키지 버전은 유지했다. 재사용 조사와 미채택 이유는 계획서에 기록했다.

## 빌드와 자동 검증

다음 명령을 실행했다.

```powershell
dotnet restore server/ElementalLegion.sln --locked-mode -m:1 -nodeReuse:false
dotnet build server/ElementalLegion.sln --no-restore -c Release -m:1 -nodeReuse:false -p:UseSharedCompilation=false
dotnet test server/ElementalLegion.sln --no-restore -c Release -m:1 -nodeReuse:false -p:UseSharedCompilation=false
dotnet server/Server/bin/Release/net10.0/ElementalLegion.Server.dll --bots 15 --report-tick
```

- Release 솔루션 빌드: 경고 0, 오류 0.
- xUnit: **90/90 통과**, 실패·건너뜀 0. 상성·비용·드롭·명령·이동·시야·14종 효과·6종 반응·전향·예약·합류·봇·통계를 검사한다.
- 막타 소유자·같은 틱 인구 회수·재전향 금지·자원 보존과 1,200틱 연속 봇 진행 중 인구·잔액·유닛 ID·체력 정합성을 확인했다.
- 수비대의 wet·연기 오라·선행 타격 출처 배제와 합류 후 소급 발동 금지, 작은/최소 비정규/최대 유한 방향의 정규화 회귀 테스트를 통과했다.
- 인수 없는 환경 확인: 종료 코드 0. 잘못된 `--bots 0`: 종료 코드 2.
- 실시간 2봇: 301틱 진행 후 `Ctrl+C`에서 `종료: ticks=301; units=2+238; attacks=118`을 출력했다. PTY를 감싼 PowerShell은 중단 상태 1을 반환하므로 자식 프로그램의 종료 코드 0을 별도 실측한 것으로 보고하지 않는다.
- 고정부하 보고: 종료 코드 0. 실패했던 최적화 전 보고는 종료 코드 3이었다.
- 고정 의존성 복원·NuGet 취약성 조회가 정상 완료됐다. 초기 제한 환경의 NU1900은 네트워크 가능한 실행에서 복원하여 해결했다.
- 공유 소스 16개 모두 `.meta`가 있으며 GUID 중복이 없음을 확인했다.

로컬 원시 기록은 `.artifacts/m0/benchmark-final.txt`, `.artifacts/m0/m0-tests.trx`, `.artifacts/m0/progress.md`에 있다. `.artifacts/`는 Git에서 제외되며 이 문서에 핵심 결과를 보존한다.

### 측정에 따른 개선

최초 밀집 p99는 14.149ms로 실패했다. 가장 가까운 표적 탐색을 전체 반경 후보 목록 순회에서 **현재 칸 우선 탐색과 칸 거리 하한에 따른 제외**로 바꾸고 버퍼 용량을 초기화 단계에 확보했다. 진형 정렬의 enum 비교가 만든 박싱도 정수 비교로 제거했다. 전체 탐색 결과와 비교하는 경계 테스트를 추가했으며, 최대 부하의 공격·사망·전향 횟수는 보존됐다. 최초 밀집 평균 탐색·오라 시간은 6.843ms, 최종은 1.761ms였다.

## Unity 확인 범위

Unity 6000.6.0f1에 포함된 Roslyn 컴파일러와 이 프로젝트의 기존 Bee 응답 파일에 있는 실제 참조·정의·분석기 설정으로 **현재 공유 소스 16개를 C# 9로 컴파일해 성공**했다. 산출물은 `.artifacts/m0/ElementalLegion.Shared.Unity.dll`이다. 새로운 의존성이나 UnityEngine 참조를 추가하지 않았다.

실제 Editor는 열려 있지 않았고 실행 중인 `unity.exe serve`는 Unity Hub 보조 프로세스였다. [작업 절차](../Rules/workflow.md)의 “Unity는 사람이 에디터에서 연다” 규칙에 따라 Editor를 새로 자동 실행하지 않았다. 따라서 **Editor 가져오기·Console 상태, Play, Windows Player 빌드와 시각 동작은 미검증**이다. 내장 컴파일러 호환성 확인을 실제 Editor 검증으로 대체 보고하지 않는다.

## 추가 값과 판단 기록

- 승인된 추가: `economy.coreDropRounding="floor"`, `economy.convertedHealthRatio=1.0`, `economy.corePickupRadius=1.5`, 모래폭풍 `triggerWindowSeconds=4.0`. 새 수치 경로를 placeholder 목록에 등록했으며 기존 밸런스는 유지했다. 습득 반경·선행 타격 시간은 플레이테스트 조정 대상이다.
- 대부분의 bootstrap 파일이 기존 미추적 작업이어서 별도 checkout 대신 현재 폴더의 `codex/m0-simulation` 브랜치에서 수정했다. 원래 변경을 보존했고 커밋·푸시는 하지 않았다. 물리적으로 분리된 worktree는 아니다.
- Windows에서 skill의 Bash 보조 명령 대신 실제 .NET 명령·TRX·진행 기록을 사용했다. 검증 증거를 남겼으며 커밋 범위로 검증했다고 주장하지 않는다.
- 공간 분할은 외부 코드를 복사하지 않고 배열 버킷으로 구현했다. 최대 부하와 정확성은 현재 범위에서 측정했으며 더 큰 월드의 성능을 보장하지 않는다.
- 핵 습득 거리는 군단 중심과 군단 유닛 중 최소 거리로 정했다. 넓은 진형의 가장자리가 지나가도 수집되며 동률은 플레이어 ID다.
- 독립 리뷰의 Important 2건(수비대 출처와 작은 방향 입력)을 각각 실패하는 테스트로 재현하고 수정했다. 최종 90/90 통과를 확인했으며 재리뷰를 수행한 것으로 보고하지 않는다. Critical·보류한 Minor는 없었다.
- 리뷰에서 제외한 최종 Release 수치는 이 작업에서 재측정했다. 실제 Editor 검증은 위 한계를 유지한다. UDP·클라이언트 통합·건설 진행·중립 생성/재생성·맵 핵 생성·유령·저장은 승인된 후속 범위다. 실제 타워 공격도 후속이며 현재는 타워 처치의 전향 금지 규칙만 검증했다.

고정부하 초기화와 최대 레벨·혼합 50기는 측정용이다. 실제 시작 인구 3기와 자원, 기존 수치를 변경하지 않았으며 실시간 M0 시나리오에는 기본 양성소만 미리 배치한다. 최소 봇은 자동 집결 지휘를 추가하지 않아 양성된 수비대가 본진에 남을 수 있다. 집결 명령과 합류 동작 자체는 코어와 테스트에서 지원한다.
