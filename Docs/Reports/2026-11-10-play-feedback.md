# 2026-11-10 플레이 피드백 반영

전장·미니맵 조작, 건설 미리보기, 밀집 효과 표시, 수비대 복귀와 귀환 후 진형을 수정했다. 게임 수치와 데이터 해시는 바꾸지 않았다. 프로토콜은 수비대 복귀·승계 규칙을 맞추기 위해 v22로 갱신했으며 패킷 길이는 유지했다. 데이터 해시는 `fdd19b348da33fd62f7aea6232215a024c2711b8b31b55966e9167b69ad82404`다.

## 바뀐 동작

- 전장에서 우클릭한 채 드래그하면 최신 목적지를 기존 20Hz 명령 전송 주기로 보낸다. 짧은 클릭도 다음 전송까지 보관한다. 방향키가 우선하며, UI·건설 취소·메뉴·채팅·포커스 상실·분대 선택·승계로 취소된 홀드는 버튼을 놓기 전까지 재개하지 않는다.
- 미니맵 우클릭·드래그는 분대 이동, 좌클릭·드래그는 카메라 이동이다. 지도 밖으로 나간 드래그와 비활성화된 화면의 입력은 이어서 실행하지 않는다.
- 지점 이동은 원형 건물 바깥의 경유점을 찾아 움직인다. 방향키 이동의 기존 충돌은 유지한다. 건물 내부를 목적지로 지정하면 표면에서 멈춘다.
- 빈 분대도 중심과 목적지를 유지한다. 처음 생성되는 2·3번 중심은 본진 옆에 두고, 전멸·집결·양성·재접속 때 원격 중심을 초기화하지 않는다. 빈 중심은 추가 시야를 만들지 않으며, 자기 건물과 직전 관측의 건물만 충돌·우회에 사용한다. 증원이 접근해 건물을 관측하면 가까운 합법 경계로 보정한다.
- 선택한 야전 분대의 **수비대로 집결** 버튼을 추가했다. 표시된 인원이 본진으로 걸어와 합류한다. 반대 방향의 기존 G 명령은 **야전 집결**로 표시한다. 여유 수비 인구만큼 요청하며 복귀·양성·전향 후보가 같은 상한을 예약한다. 지정 수량 재편도 수비대가 목적이면 먼 곳에서 요청할 수 있다. 복귀 중 중립을 전향시키면 새 원소도 걸어오며, 사망·저장·재접속·승계에서 예약을 중복 집계하지 않는다.
- 양자 이동 직후에는 합법 도착 배치를 유지하고, 새 이동을 지시하면 역할별 일반 진형으로 돌아간다.
- 건설 목록과 시설 선택 상태 모두 같은 바깥 경계를 표시한다. 건물 전체가 그 안에 있어야 한다는 서버 판정은 유지한다. 유효 미리보기를 밝은 색으로 표시하고 원소·건물·건설 범위의 소속 선을 얇게 했다. 프리팹에는 원소 링 8%, 큰 경계 1%를 저장했다.
- 상시 분대 원과 방벽의 중복 회전 고리를 제거했다. 하얀 중심점, 분대 번호 표식, 양자 이동 전용 효과는 유지한다. 얼음·방벽 효과의 가로 크기도 밀집 시 몸체의 표시 반경을 따른다.

## 원인과 검증 범위

중심에는 개별 원소와 달리 건물 우회가 없었다. 귀환 좌표를 일반 진형 슬롯으로 계속 사용하므로 이동 후에도 원형 배치가 남았다. 두 동작을 규칙 테스트로 재현한 뒤 수정했다.

사진의 회전 고리와 일치하는 방벽 표시 경로를 확인했다. 몸체만 밀집도에 맞춰 축소하고 얼음·방벽 효과는 고정 크기로 그리던 경로도 재현했다. 합성 스냅샷의 수정 전후 화면과 실제 렌더 배치 검사를 확인했다. 다만 원본 사진의 서버 좌표 중첩은 재현하지 못했다. 별도의 야전 8기·증원 4기 시험에서는 합류 후 300틱에서 모든 쌍이 JSON의 최소 간격을 유지했다. 시너지는 원소 좌표를 겹치게 만드는 규칙이 아니다.

기존에 전멸한 분대를 본진으로 옮기던 테스트는 새 요구에 맞춰 원격 중심 보존으로 바꿨다. 확보 권한 검사는 증원의 도착 상태를 명시적으로 준비해 보행 시간과 분리했다. 전멸한 분대의 권한이 새 병력으로 복구되지 않는다는 단언은 유지했다.

지점 탐색은 한 경로의 원형 장애물 16개·후보 258개·간선 검사 8,192회로 제한한다. 예산이나 경로가 부족하면 관통하지 않고 멈춘다. [소규모 경로 진단](../../.artifacts/movement-feedback-nav-probe/results.md)은 전체 전장 성능이나 최신 수정본의 최대 부하 통과 근거가 아니다.

## 재사용 조사

2026-11-10에 [Unity의 포인터 이벤트 문서](https://docs.unity.cn/Packages/com.unity.ugui@3.0/manual/SupportedEvents.html), [Reynolds의 장애물 회피 설명](https://www.red3d.com/cwr/steer/Obstacle.html), [RVO2](https://github.com/snape/RVO2)를 확인했다. RVO2는 Apache-2.0의 C++ 구현이므로 현재 C# 공유 코어에 연결하는 비용이 크다. 기존 uGUI·Input System·원형 충돌 계산과 표현 메시를 재사용하고 제한된 경유점 탐색만 독자 구현했다. 외부 코드·에셋·패키지는 추가하지 않았다.

## 직접 확인 순서

서버와 Unity를 모두 최신 소스로 사용한다. `Start-Server.cmd`의 3번 M4 데모를 실행하고 Unity에서 접속한다. 우클릭 드래그로 본진 반대편에 이동한 뒤 미니맵 양쪽 버튼을 시험한다. 야전 분대 하나를 골라 수비대 집결을 누르고, 귀환 후 이동했을 때 일반 진형으로 정렬되는지 확인한다. 건설 미리보기는 같은 시설을 범위 안·경계·밖으로 옮겨 비교한다.

## 추가 수정: 게임 창 클릭 후 원소가 사라지는 오류

앞서 통과한 145개 테스트에는 파괴된 UI가 선택된 상태에서 게임 창에 포커스가 있는 경우가 없었다. `AcceptsGameplayInput`의 `?.` 검사는 Unity에서 파괴된 객체를 걸러내지 못했다. 이때 `GetComponent` 예외가 원소 렌더링 전에 발생하므로 하얀 중심점만 남았다. 창 밖에서는 포커스 조건이 거짓이 되어 해당 검사를 건너뛰었다.

입력 검사에서 Unity의 null 비교로 EventSystem·선택 객체·입력 필드를 확인하도록 수정했다. 두 호출자는 기존 앱 포커스 조건을 그대로 전달한다. 채팅·메뉴·실제 텍스트 편집 중 입력 차단도 유지한다. 서버·공유 코드·게임 데이터는 이번 수정에서 변경하지 않았다.

Editor에서 기존 예외를 재현한 뒤 수정했다. 관련 테스트는 **14/14**, 전체 EditMode는 **149/149 통과**했고 컴파일 오류는 없었다. [재현 결과](../../.artifacts/input-selection-fix/red.json), [수정 후 관련 테스트](../../.artifacts/input-selection-fix/green.json), [전체 테스트](../../.artifacts/input-selection-fix/editmode.json), [컴파일 결과](../../.artifacts/input-selection-fix/compile.json)를 보존한다. 최초 테스트 환경의 EventSystem 등록 오류는 `fixture-errors.json`으로 따로 보관했다. 실제 Play 클릭과 Windows Player의 화면 복구는 아직 확인하지 않았다.

## 추가 피드백: HUD 조작 중 이동과 분대 번호 위치

일반 HUD의 선택이나 수량 입력은 이동을 막지 않도록 요구를 갱신했다. 기존의 모든 텍스트 편집 차단 테스트도 이 요구에 맞췄다. `ClientBootstrap`은 일반 UI의 선택·포커스를 이동 허용 조건에서 제외하고, 채팅 작성·메뉴·화면 전환·서버 승계·앱 포커스에 따른 차단을 유지한다. 승계 후 이동 방향을 보내는 경로에서도 일반 UI 조건만 제거했다. 재편 수량 입력 중 이동이 막히는 조건을 [수정 전 테스트](../../.artifacts/hud-feedback-20261110/input-red.json)로 재현했다.

분대 마름모는 고정된 중심·반경·높이 대신 실제로 그린 자기 분대 몸체의 화면 범위 바로 위 중앙에 배치한다. 보간·예측·밀집 크기가 적용된 메시와 주 몸체 입자의 범위를 합친다. 합류 중인 증원은 도착 후부터 반영하고, 마름모 개수와 스타일은 유지했다. 새 표현 수치나 패키지·프리팹·서버·공유 코드 변경은 없다. 기존 `squadMarkSize`를 몸체 위 여백에도 사용한다.

Unity 컴파일 오류 없이 전체 EditMode **154/154 통과**했다. [컴파일](../../.artifacts/hud-feedback-20261110/compile.json)과 [테스트 결과](../../.artifacts/hud-feedback-20261110/editmode.json)를 보존한다. 회전한 카메라에서 메시·입자 몸체, 밀집·분산, 보간·예측과 1~4번 표식을 검사했다. 같은 전장 구성의 [수정 전](../../.artifacts/hud-feedback-20261110/visual/markers-before.png)과 [수정 후](../../.artifacts/hud-feedback-20261110/visual/markers-after.png)를 Editor 카메라로 확인했다. 직접 수행하는 Play 조작, Windows Player와 GPU 성능은 확인하지 않았다.
