# M1 폴더 정리와 접속·이동 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Unity 자산 배치 규칙을 확정하고 기존 참조를 보존해 정리한 뒤, 로컬 두 클라이언트의 서버 권위 군단 이동을 구현한다.

**Architecture:** `shared/Runtime/Net`에는 검증 가능한 패킷·설정·전송 계약을, 서버에는 세션과 고정 틱 UDP 호스트를 둔다. Unity는 하나의 시작 컴포넌트가 입력·세션·예측/보간·파티클 표시·접속 UI를 명시적으로 연결한다. 시야 필터는 처음부터 적용하며 전체 월드나 서버 집계를 전송하지 않는다.

**Tech Stack:** Unity 6000.6.0f1 / URP 17.6.0 / Input System 1.20.0 / uGUI 2.6.0, LiteNetLib 1.3.5, Newtonsoft.Json 기존 버전, C# 9 / netstandard2.1 공유 코드, .NET 10 서버와 xUnit.

**Spec:** 사용자 승인 순서와 `Docs/Rules/workflow.md`의 M1, `Docs/Rules/architecture.md`, `Docs/protocol.md`. 폴더 설계는 `Docs/Rules/project.md`가 단일 원본이다.

## Global Constraints

- 프로젝트 구성 규칙 기록 → 기존 자산 정리·참조 확인 → M1 구현 순서를 지킨다.
- 기존 Git 변경은 사용자 소유다. 커밋·스테이징·브랜치 변경·리셋·푸시는 하지 않는다.
- 열린 Editor와 사용자 변경을 유지하기 위해 현재 체크아웃에서 수행한다. 별도 worktree의 Editor나 자산을 대신 조작하지 않는다.
- 게임 수치는 `shared/Data/gamedata.json` 원본을 유지한다. 표현 수치만 인스펙터에 노출한다.
- 위치·피해·결과를 클라이언트 명령으로 받지 않는다. 숨겨진 유닛·군단 중심·이벤트는 보내지 않는다.
- M1은 접속·이동이다. 안개 렌더링, 탐색 기록, 전투 이벤트 표현, 건설, 저장, 재접속 복원은 후속 단계다.
- 새 패키지는 추가하지 않는다. 자산 이동은 AssetDatabase를 통해 GUID를 보존한다.
- 순수 규칙·통신 검증은 자동 실행한다. 저장소 규칙에 따라 Unity Play와 시각 동작의 최종 확인은 사람이 수행한다.

## Review Focus

- 잘린 패킷·과대 길이·잘못된 버전·비유한 방향·존재하지 않는 원소가 상태를 변경하지 않아야 한다 → ProtocolTests.
- 다른 플레이어 명령 위조, 데이터 해시 불일치, 최대 접속 초과를 거절해야 한다 → SessionTests / UDP 통합 검사.
- 접속 종료·재접속·ID 재사용으로 이전 입력이 새 군단을 움직이지 않아야 한다 → MembershipTests.
- 유실·역순 스냅샷과 입력 확인 번호에서 예측이 중복 적용되거나 상대가 순간 이동하지 않아야 한다 → ClientMotionTests.
- 폴더 이동 후 씬·렌더 파이프라인·Input Actions의 GUID, Build Settings 참조, 컴파일을 보존해야 한다 → Editor 구조 검증.

## 승인된 구조 설계

유형별 폴더만 쓰는 방식과 기능마다 모든 자산을 묶는 방식을 비교했다. 현재 규모에는 `Assets/_Project` 아래 자산 유형을 구분하고 `Scripts/Runtime` 안에서 기능을 구분하는 혼합 구조를 제안했고 사용자가 순차 적용을 승인했다. 빈 미래 폴더는 만들지 않고 원본 규칙에 예약 경로를 기록한다. Runtime·Editor·테스트의 어셈블리 경계를 우선 분리한다.

M1은 계정 인증이 없는 로컬 개발 접속이다. 연결 요청의 프로토콜 버전·JSON 해시·시작 자연 원소를 검사하고 서버가 새 세션의 소유자 ID를 정한다. 연결 종료 시 입력만 정리하고 군단·본진·자원을 보존하며 유령 만료·재접속 복원은 M4/M5에서 구현한다. M0 콘솔 모드는 유지하고 UDP 실행은 `--listen`으로 명시한다.

## 재사용 조사 (2026-11-02)

- [Unity 프로젝트 정리 가이드](https://unity.com/how-to/organizing-your-project): 전용 루트·문서화·GUID 보존 원칙을 적용한다. 외부 소스 복사 없음.
- [LiteNetLib 원본](https://github.com/RevenantX/LiteNetLib): 기존 고정 1.3.5 / MIT의 NetManager·NetDataReader/Writer·시퀀스 전송을 재사용한다. 네트워크 프레임워크를 추가하지 않는다. 고지는 `shared/Plugins/LiteNetLib.LICENSE.txt`.
- [Unity Input System](https://github.com/Unity-Technologies/InputSystem): 설치된 1.20.0과 기존 Player/Move·UI Action Map을 재사용한다. 별도 입력 패키지 없음.
- [Unity Particle Pack](https://assetstore.unity.com/packages/vfx/particles/particle-pack-starter-assets-127325): 무료·Standard Asset Store EULA를 확인했다. 다운로드 크기와 전투 연출 범위가 M1 이동 표시보다 커서 도입하지 않는다. Unity 내장 Particle System의 소수 마커로 시작하고 VFX 제작 단계에서 재검토한다. URP 실사용 호환성은 미검증이다.
