# M2 서버 시야·탐색 기록과 3D 우주 연무

> 실행: superpowers:executing-plans. 사용자가 이 설계의 구현을 승인했다. 현재 Editor와 사용자 변경을 유지하며 커밋·스테이징·브랜치 변경 없이 진행한다.

## 승인한 목표

서버가 허용한 정보만 전송하면서 미탐색·탐색됨·현재 시야를 실제 3D 볼륨 연무로 구분한다. 1080p·60fps 우선이며 게임 밸런스·시야 반경은 유지한다. M1은 사용자 Unity 접속 확인만 기록하고 두 클라이언트 이동·보간의 수동 확인은 보류한다.

## 작업과 검증

- [x] 1. VisionGrid: JSON의 mapSize/visionCellSize로 현재/누적 탐색 비트맵을 생성한다. 원과 겹치는 지형 칸만 표시하고 기존 유닛 원 거리 판정은 유지한다. 공유 코드는 C#9/netstandard2.1, UnityEngine 비의존이다. 경계·복수 원천·소멸/전향·누적·격리 테스트를 먼저 실행한다.
- [x] 2. 프로토콜 v2: 별도 신뢰 순서 채널에 시야 기준 상태·변경분·이전에 관측한 ID 표시 해제를 전송한다. 1024B 이내 청크는 revision별 원자 적용한다. 유닛 상태에는 시야 revision을 추가하고 미래 상태는 최신 완성 프레임 하나만 대기시킨다. 늦은 상태로 해제 ID를 되살리지 않는다. 끊김/새 접속은 전부 미탐색으로 초기화한다. 실제 패킷·오류·역순·유실 조각 테스트를 포함한다.
- [x] 3. URP17.6 RenderGraph 3D 볼륨: 절차적 반복 3D 노이즈, 높이 감쇠·바람·청록/보라 밀도장, 단일 방향광/주변광의 산란·흡수. 기본 반해상도32샘플/높이24m, 낮음 반해상도16, 높음 전체해상도64. 다중 산란·볼륨 그림자·시간 누적·자동 품질 변경 없음. 투명 파티클 뒤/후처리 앞에 깊이 고려 업샘플링과 합성. 깊이가 없는 배경은 바닥/볼륨 경계로 적분 제한. 미탐색은 검정 차폐, 탐색 지형은 어둡게, 현재 시야는 옅은 연무. 시각 수치는 인스펙터, 반경은 JSON 고정. 카메라별 자원 소유/해제와 UI 보존을 검사한다.
- [x] 4. 플레이어별 트래픽: 앱 payload와 LiteNetLib Bytes/Packets를 분리한다. 재전송 포함, UDP/IP 헤더 제외를 명시한다. 평균/최대1초 KiB/s, 초기 동기화와 정상 진행을 구분한다. `--listen --report-network`로 세션/서버 종료 시 틱 밖에서 요약한다. 정지·이동·시야 진입/이탈·밀집 관측을 측정한다.
- [ ] 5. 전체 검증: 실제 두 UDP 클라이언트, .NET 전체 빌드/테스트, Unity 컴파일/EditMode, 같은 PC의 M0 분산·밀집 부하 전후 비교. RTX3070 Laptop/D3D11의 1080p 연무 추가GPU p95≤3ms는 측정 목표이며 미측정/미달을 그대로 기록한다. Play/Windows Player·실제 시각 품질과60fps는 사람이 수행하고 불가능하면 보류한다.

## 고정할 인터페이스

- `WorldView.Vision`: 외부에는 읽기 전용 VisionGrid 제공. 서버 시야 단계가 현재값과 누적값을 갱신한다.
- `FogReplicationState`: 서버 peer별 마지막 전송 비트맵·관측 ID·revision, 초기 기준/변경분/표시 해제 준비와 전송 후 commit.
- `FogStateReplica`: 순수 C# 청크 검증·기준/증분 원자 반영. 표시 해제 틱은 Timeline이 기록한다. ClientConnection이 관리하고 FogPresentation/Timeline이 읽는다.
- `UnitSnapshotAssembler.Revision`: 시야 revision과 묶인 유닛 프레임. 동일 틱의 모든 조각에서 revision도 같아야 한다.
- `SnapshotTimeline.Forget`: 해제 틱 이하 상태를 그리지 않는다. 다시 관측한 더 최신 상태는 허용한다.
- `FogPresentation`: 카메라별 텍스처·머티리얼과 서버 시야 투영 수명. `FogOfWarRendererFeature`가 카메라별 자료를 명시적으로 등록/해제한다.
- `NetworkTrafficReport`: peer별 평균/최대1초/페이로드 종류/연결시간과 전송 통계.

## 패킷·자원 기본 결정

기존 제어/이동 채널0, 시야 신뢰 채널1을 사용한다. 기준/변경분은 같은 revision의 청크 조립 후 교체한다. 셀 인덱스는 int32, 비트맵은 packed bytes다. 표시 해제에는 이전에 본 ID와 해제 틱만 있으며 숨겨진 위치/상태/사건을 넣지 않는다. 미완성 배치와 미래 유닛 버퍼는 한 revision/프레임으로 제한한다. 초기 기준은 시뮬레이션과 세션의 현재 관측에서 생성하며 파일 저장·계정 복원은 M5다.

렌더러는 원본 feature 목록을 보존하고 Game Base 카메라 중 등록된 카메라만 처리한다. 현재 color/depth descriptor를 바탕으로 반해상도 RGBAHalf 연무와 전체 해상도 합성을 만든다. 공유 전역 마스크 없음. 레이 적분은 전방→후방, 투과율이 충분히 낮아지면 조기 종료한다. 3D 노이즈는 Editor에서 고정 시드로 한 번 생성하고 런타임에 재생성하지 않는다.

## 실행 기록

기준: .NET106/106. 이 PC SDK10.0.302를 직접 호출하며 global.json의10.0.401은 유지한다. M1과 사용자의 변경은 기준 상태로 보존한다. 미니맵·카메라 드래그·교전 신호·전투 연출·저장·재접속은 추가하지 않는다.

구현과 자동 검증은 완료했다. .NET126/126, Unity EditMode8/8, 실제 두 UDP 접속·시나리오 대역폭, 같은 PC M0 전후와 Editor GPU를 기록했다. 독립 리뷰의 두 차폐 결함은 실패 재현 후 수정했다. 전체5번 체크는 밀집10ms 목표 미달과 실제 Play/Windows Player·전체 GPU/60fps 보류를 포함하므로 완료로 표시하지 않는다. 상세 수치·재현·판단은 [M2 검증 보고서](../Reports/2026-11-02-m2-validation.md)를 따른다.
