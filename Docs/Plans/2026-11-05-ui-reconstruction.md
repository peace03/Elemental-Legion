# 시안 기반 UI 재구성 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. 현재 작업 트리의 사용자 변경을 보존하고 이 계획 범위만 수정한다.

**Goal:** 승인된 씬별·상황별 시안의 남색·금색·청록색 스타일과 아이콘 중심 배치를 현재 Unity UI에 적용한다.

**Architecture:** 기존 uGUI / TMP와 `ClientFlow → ClientScreen / ClientSettingsScreen / CombatHud`의 표시·입력 전달 구조를 유지한다. `ObservatoryUi`를 공통 표현 지점으로 사용하고, 재사용할 아트 설정과 프레임 표현만 추가한다. 새 네트워크·게임 판정 계층을 만들지 않는다.

**Tech Stack:** Unity 6000.6.0f1, URP 17.6.0, uGUI 2.6.0, TMP, 기존 Input System.

**Spec:** `Docs/Art/Concepts/2026-11-05-scenes/prompts.json`과 최종 16개 PNG, 이번 대화의 UI 재구성 요청.

## 요구와 범위

- 타이틀·서버/방 찾기·방 만들기·비밀번호·대기실·설정·현황·상성표·ESC·패배·접속 복구 UI와 전장 HUD에 일관된 스타일을 적용한다.
- 시설은 모델로 제작한다는 기획을 UI의 시설 아이콘과 배경에 반영한다. 월드의 실제 시설 메시·원소/VFX 모델링은 이번 UI 변경에 포함하지 않는다.
- 예시 이미지의 수치·가짜 명령·오타를 옮기지 않는다. 비용·시간·해금·인구·상성은 기존 서버 상태와 JSON을 사용한다.
- 닉네임·방 제목·채팅의 rich text 차단, 비밀번호 검증, 준비·방장·접속 복구 중 잠금, 설정 되돌리기, 키 충돌 검사, 훈련 취소를 보존한다.
- 원소 14종과 시설 6종의 그림을 공용 아이콘으로 사용하고, 실제 한글과 수치는 TMP로 그린다.
- 1280×720, 1920×1080, 2560×1440 및 UI 90~110%에서 주요 버튼·표시가 겹치거나 잘리지 않게 검증한다.
- 현재 작업 트리의 서버 인계·이동·역할 표시 관련 변경을 보존한다. 커밋·푸시·다른 브랜치로의 전환은 요청 범위에 넣지 않는다.

## 변경 지점

- 공통: `ObservatoryUi.cs`, 필요한 공용 아트 설정·uGUI 프레임·아이콘 자산.
- 메뉴: `ClientScreen.cs`, `ClientScreen.Rooms.cs`, `ClientSettingsScreen.cs`.
- 전장: `CombatHud.cs`, `ConstructionPanel.cs`, 필요한 `FieldChat.cs`의 배치·표현 부분.
- 연결: 필요할 때만 `ClientFlow.cs`의 UI 자산 전달·초기화 부분, Editor의 자산 임포트·참조 구성.
- 검증: 기존 EditMode 검증에 새 UI의 입력 전달·레이아웃 경계·자산 연결 검사를 추가한다. 기존 테스트는 유지한다.

## 재사용 조사 (2026-11-05)

- https://kenney.nl/assets/ui-pack-sci-fi : 공식 페이지의 2.0, 130개, CC0를 확인했다. 버튼·패널 후보지만 시안의 금속·원소 그림과 차이가 있어 이번에는 새 팩을 가져오지 않는다.
- https://github.com/Unity-Technologies/uGUI : 설치된 uGUI를 재사용한다. 프레임워크를 교체하거나 외부 코드를 복사하지 않는다.
- https://docs.unity3d.com/Packages/com.unity.ugui@2.0/manual/HOWTO-UIMultiResolution.html : CanvasScaler와 앵커를 이용하는 기존 해상도 대응을 유지한다.
- 기존 Noto Sans KR / TMP, Particle Pack / Kenney 파티클을 보존한다. UI 배경과 원소·시설 아이콘은 승인된 시안에 맞춰 내장 이미지 생성 도구로 만든다.

## 검증에서 중점적으로 볼 사항

1. 최대 15명 대기실과 긴 한글 닉네임·방 제목의 잘림/줄바꿈.
2. UI 확대 상태의 미니맵·양성 목록·건설 목록·채팅 간 겹침.
3. 비활성·선택·마우스 올림·키보드 포커스 표시와 장식의 입력 가로채기.
4. 재접속/서버 인계 중 비활성 상태와 늦게 도착한 상태 갱신 보존.
5. 설정·현황·메뉴 반복 열기/닫기의 중복 이벤트·글꼴/스프라이트 수명.

- [x] 1. 현재 Unity 연결과 컴파일·테스트 기준선을 기록한다. 기존 UI 호출자와 참조를 확인한다.
- [x] 2. 실제 화면·입력 동작을 검증하는 작은 회귀 테스트를 먼저 추가하고 기존 UI에서 실패를 확인한다.
- [x] 3. UI용 배경·원소·시설 그림과 공통 프레임/컨트롤 스타일을 연결한다. 자산·가독성 검증을 통과시킨다.
- [x] 4. 타이틀·서버·방·대기실·설정·현황·상성표·모달의 배치를 적용한다. 기존 콜백과 검증을 유지한다.
- [x] 5. 전장 상단 상태·미니맵·양성·건설·집결·채팅의 배치를 적용한다. 서버 상태 표시와 훈련 취소를 검증한다.
- [x] 6. .NET 빌드·테스트, Unity 컴파일·EditMode 및 가능한 비파괴 시각 검증을 실행하고 변경분을 리뷰한다. 사람의 Play 확인은 별도로 구분한다.

## 진행 기록

- 요구 확인: 사용자가 16개 이미지 시안을 참고한 현재 프로젝트 UI 재구성을 요청했다. 시안을 UI 표시 설계로 적용하고, 기존 게임·연결 기능을 보존하는 범위로 해석했다.
- Graphify를 갱신해 공통 팩터리와 메뉴/HUD 호출 지점을 확인했고, 부분 클래스·네임스페이스 중복 경고가 있어 원본과 `rg`를 함께 확인했다.
- Unity CLI는 sandbox 밖 읽기에서 프로젝트 `client`, Unity 6000.6.0f1, Main Editor PID 5348, ready를 확인했다. sandbox 안에서는 인스턴스가 숨겨져 직접 연결 명령은 필요한 범위에서 실행한다.
- 배경 1장, 원소 14종·시설 6종 아이콘, 공용 아트 설정과 모서리를 잘라 낸 프레임을 연결했다. 메뉴·설정·대기실·현황과 전장 HUD에 적용했다.
- 리뷰와 실제 렌더링에서 찾은 스프라이트 좌표, 타이틀 잘림, 미리보기 한글 글꼴, 미니맵 텍스처 정리, 양성 설명 줄 간격을 수정했다. 회귀 테스트로 재발 조건을 확인했다.
- 최종 검증: Unity 컴파일 오류·경고 0개, 전체 EditMode 25/25, .NET 빌드 오류·경고 0개와 테스트 307/307, 13개 화면 × 3개 해상도 × UI 90·100·110%의 117개 렌더링에서 화면 밖 조작 요소 0개.
- 원래 Bootstrap 씬은 Play에 진입하거나 저장하지 않았으며 검증 후 한 개 씬·수정되지 않은 상태로 남았다. Play·Windows Player·실전 성능 측정은 하지 않았다.
