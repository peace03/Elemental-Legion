# M5 구현 계획 — 방 만들기, 인터넷 방 찾기, 재접속, 저장, 채팅

**목표**는 다른 집에 있는 플레이어도 서버 주소를 몰라도 방 제목을 보고 입장할 수 있게 하는 것이다. 방장이 게임을 시작하면 같은 전장에 들어가고, 연결이 끊겨도 같은 PC에서 유령 기지로 복귀할 수 있다. 기존 상시 월드와 로컬 데모는 지금의 입장 흐름을 사용한다.

현재 서버 찾기 화면은 이 PC에 저장된 주소 목록을 보여준다. v10 서버는 접속을 승인하면 바로 월드에 플레이어를 생성한다. 방 상태와 게임 시작 권한을 그 앞단에 추가한다. 게임 판정과 시야 필터는 기존 공유 코어에 둔다. [현재 입장 흐름](../../client/Assets/_Project/Scripts/Runtime/Bootstrap/ClientFlow.cs) · [네트워크 규칙](../Rules/architecture.md) · [현재 프로토콜](../protocol.md)

## 0. 인터넷 전송 검증

- 인터넷 모드는 **운영자가 호스팅하는 .NET 10 전용 서버**에 방 목록과 게임 접속을 모은다. 첫 배포는 단일 호스트의 ASP.NET Core 진입점과 방마다 독립적인 `NetworkWorld`를 사용한다. 방장 버튼은 서버에 새 방을 요청한다. 모든 참가자는 고정 서비스 도메인의 **HTTPS/WSS 443**으로 접속하므로 집에서 포트 포워딩할 필요가 없다. 공개 인터넷에서는 온라인 진입점만 열고, 로컬 게임의 UDP 포트와 저장·관리 경로는 외부에 노출하지 않는다. [ASP.NET Core WebSocket](https://learn.microsoft.com/en-us/aspnet/core/fundamentals/websockets?view=aspnetcore-10.0)
- 온라인은 기존 패킷 코덱과 시야 필터를 재사용한다. Unity Windows 클라이언트의 `ClientWebSocket`과 ASP.NET Core로 송수신을 연결하고, 네트워크 작업은 방의 단일 스레드에 제한된 큐로 전달한다. 로컬 UDP는 기존 신뢰·비신뢰 채널을 유지한다. 온라인 WSS는 TCP이므로 손실 시 뒤의 패킷도 늦어질 수 있다. 전송 대기 중인 위치 스냅샷은 최신 완성 묶음만 남기고, 명령 결과·시야 변경은 순서대로 보낸다. 느린 연결은 대기 상한을 넘으면 종료하고 재접속으로 복구한다. [클라이언트 API](https://learn.microsoft.com/en-us/dotnet/fundamentals/networking/websockets) · [기존 스냅샷 규칙](../Rules/Patterns/networking.md)
- 본 구현에 앞서 Unity Editor와 **실제 Windows Player**에서 인증서가 유효한 WSS 연결, 만료·이름 불일치 인증서 거절, 양방향 바이너리 송수신을 확인한다. RTT 80ms, 지터 20ms, 손실 1%를 재현해 입력부터 서버 확정 응답까지 p95 250ms 이내인지 확인한다. 이 값은 초기 온라인 검증 기준이다. WSS는 기존 위치 전송 규칙의 온라인 예외이므로 통과 후 프로토콜 문서에 구분해 반영한다. 호환성이나 지연 기준을 통과하지 못하면 인터넷 공개를 보류하고 전송 방식을 재검토한다.

## 1. 방 만들기 → 방 찾기 → 대기실 → 게임 시작

- 타이틀의 **게임 시작**에서 **방 만들기**와 **방 찾기**를 연다. 생성 시 방 제목, 최소 시작 인원, 정원을 입력한다. 최소 시작 인원 기본값은 방장 포함 **2명**, 최대 정원은 현재 규칙의 **15명**이다. 방 제목은 앞뒤 공백을 제거한 한 줄로 최대 32자다. 서버가 제목·인원 범위·생성 권한을 검증하고 고유 방 ID를 발급한다. 온라인은 중앙 서버가 방을 열고, LAN은 배포에 포함된 로컬 서버 실행 파일을 게임에서 실행한다.
- 방 찾기는 **인터넷**, **같은 네트워크**, **저장한 주소**를 나눠 표시한다. 온라인 목록에는 중앙 서비스가 운영하는 공개 방과 운영자가 공개한 상시 월드를 올린다. LAN 목록은 LiteNetLib의 로컬 검색으로 채운다. 목록에는 방 제목, 현재 인원, 정원, 대기·게임 중 상태를 표시한다. **입장**을 누르면 게임이 대상과 접속 경로를 처리한다. 응답하지 않는 LAN 방은 새로고침에서 제외하고, 목록이 오래됐거나 방이 찼다면 실제 입장 실패 사유를 표시한다. [LiteNetLib 로컬 검색](https://github.com/RevenantX/LiteNetLib/blob/master/docs/index.html)
- 대기실은 참가자 닉네임, 방장, 선택한 시작 원소와 준비 상태를 표시한다. 대기 중에는 월드 자산을 생성하지 않는다. 최소 인원이 모이고 방장을 포함한 현재 참가자 전원이 준비하면 방장의 **게임 시작**을 활성화한다. 서버는 입장 순서대로 임시 월드에서 시작 위치를 배정한다. 전원 배치에 성공했을 때만 `Waiting → Running`을 한 번 확정하고 전장을 공개한다. 준비 상태가 바뀌거나 배정할 자리가 부족하면 대기실을 유지한다.
- 방장이 대기실을 나가면 가장 먼저 들어온 남은 참가자가 방장을 맡는다. 게임을 시작하면 참가자 명단을 확정하고 해당 참가자의 재접속을 허용한다. 대기실이 비면 방을 닫는다. 시작한 방은 마지막 접속자와 유령이 모두 없어질 때 종료하고 목록에서 내린다. 게임 중 방장 이탈은 기존 유령 전환 규칙을 따른다.

온라인 진입점은 `GET /rooms`로 목록을 조회하고, 인증된 `POST /rooms`와 `POST /rooms/{roomId}/tickets`로 방 생성과 입장권을 처리한다. 준비·시작·게임 명령은 입장권을 교환해 연결한 WSS 세션에서 처리한다. LAN의 방 만들기는 고정된 배포 경로의 실행 파일을 인수 목록으로 실행한다. 최초 방장 권한은 부모 프로세스가 자식 서버에 비공개로 전달한 일회용 값과 루프백 접속을 확인해 부여한다. LAN 모드는 신뢰하는 로컬 네트워크에서 사용한다.

## 2. 계정과 인터넷 입장 보안, 유령 기지 복귀

| 경계 | 서버가 적용할 규칙 |
| --- | --- |
| 계정 | `IAccountStore`에서 닉네임과 계정을 구분한다. 첫 접속 시 암호학적 난수로 32바이트 키를 발급한다. 서버는 키의 SHA-256 해시를 정상 기록한 뒤 발급을 완료하고, Windows 클라이언트는 현재 사용자 DPAPI로 보호한다. 인터넷과 LAN의 키 저장 범위를 분리한다. |
| 방 목록·입장 | 인터넷은 인증된 계정으로 방을 만들거나 입장권을 요청한다. 서버가 **30초 유효한 일회용 입장권**을 계정·방·입장 목적에 묶어 발급한다. 클라이언트는 검증된 고정 서비스 도메인에만 연결하고 WSS의 첫 메시지에 입장권을 보낸다. 서버는 한 번만 소비하며, 만료·재사용·다른 방의 입장권과 이미 접속 중인 계정을 거절한다. |
| 방장·전투 권한 | 방 시작 요청의 계정과 현재 방장, 방 상태를 서버에서 대조한다. 전투 명령의 플레이어 ID는 연결에서 가져온다. 방 ID, 준비 여부, 명령 순번을 검증하고, 클라이언트가 지정한 소유자·피해·위치나 다른 방 데이터에 대한 요청은 권한으로 인정하지 않는다. |
| 공개 경로 | 공인 도메인과 정상 인증서를 사용한다. 인증서 검증과 호스트 이름 검증에 실패하면 접속을 종료한다. TLS 1.2 이상을 허용하고 지원 환경에서 1.3을 사용한다. 서버가 발급한 경로만 연결하며 외부에서 방 주소를 등록하는 API는 만들지 않는다. 키·입장권·채팅 본문은 URL·로그·방 목록에 남기지 않는다. |

운영 설정으로 계정당 대기방 1개, 초기 온라인 동시 방 4개, 인증 전 접속 대기 5초를 적용한다. HTTP 요청은 IP·계정별로, 연결 후 메시지는 세션별로 속도를 제한한다. 온라인 바이너리 게임 메시지는 기존 **1,024바이트** 상한을 적용하고, 나뉘어 도착한 메시지도 합친 크기를 검증한다. WSS 압축을 끄고 인증과 입장 확인이 끝난 뒤에만 방 데이터를 전송한다. 송수신 대기량에 상한을 두고, 인증 실패·과다 요청·비정상 종료를 비밀값 없이 집계한다. 운영자는 신규 방 생성을 끄고 악용 계정의 키와 세션을 폐기할 수 있다. [OWASP WebSocket 보안](https://cheatsheetseries.owasp.org/cheatsheets/WebSocket_Security_Cheat_Sheet.html) · [TLS 지침](https://cheatsheetseries.owasp.org/cheatsheets/Transport_Layer_Security_Cheat_Sheet.html) · [Windows DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)

복귀할 때는 같은 PC의 계정 키로 다시 인증하고 해당 방의 새 입장권을 받는다. 기존 유령이 **600초 안에** 살아 있으면 기존 플레이어 ID, 기지, 군단, 남은 핵과 탐색 기록을 복원한다. 이전 세션의 명령 번호와 전송 버퍼를 정리하고 현재 시야를 새로 보낸다. 상시 월드에서 기지가 파괴·만료됐다면 시작 원소를 골라 안전한 위치에 새로 입장한다. 이미 시작한 방에서 복귀 자격을 잃었다면 방 목록으로 돌아간다. 서버가 켜져 있으면 마지막 접속자가 나가도 유령 시간이 진행되고, 꺼져 있는 동안은 멈춘다.

## 3. 월드 저장과 재시작

- 서버 전용 `IWorldStore`에 **상시 월드와 진행 중인 방을 각각 별도 파일**로 저장한다. 방 ID와 참가 계정 연결, 월드 틱, 기지·군단·핵, 탐색, 전투 상태와 막타 귀속, 중립 재생성·유령 타이머, 다음 개체 ID를 보존한다. 복원할 때 공간 인덱스와 현재 시야를 다시 계산한다. 대기실과 접속권은 메모리에 둔다. 다시 시작한 서버는 진행 중이던 방의 복귀 접속을 받는다.
- 방이 시작되면 첫 저장을 예약하고, 이후 기본 **60초**마다 틱 경계에서 복사본을 만든다. 파일 쓰기는 백그라운드에서 실행한다. 같은 폴더의 임시 파일을 검증한 뒤 정상본을 교체하고 직전 정상본을 보존한다. 저장 형식과 데이터 해시가 맞지 않으면 원본을 보존하고 해당 월드를 열지 않는다. 손상된 정상본은 검증된 백업으로 복원한다. 닫힌 방에는 종료 기록을 남겨 이전 체크포인트가 다시 열리지 않게 한다. 정상 종료 때는 마지막 저장 결과를 확인한다. 강제 종료 시 마지막 정상 저장 이후의 진행은 유실될 수 있다.
- 서버 재시작 전 접속 중이었던 플레이어는 복원 시 유령으로 전환한다. 정해둔 대로 **진행 중인 양성·건설을 취소하고 비용과 예약 인구를 한 번만 반환**한다. 이미 유령인 경우 저장된 남은 시간을 이어간다. 온라인 방의 저장과 복귀 정보는 방 ID별로 분리해 다른 방이나 일반 서버에 섞이지 않게 한다. [저장 규칙](../Rules/Patterns/data.md) · [.NET 파일 교체 API](https://learn.microsoft.com/en-us/dotnet/api/system.io.file.replace?view=net-10.0)

## 4. 근접·전체 채팅

- 전장에서 `Enter`로 채팅을 열고 전송하며, `Esc`로 입력을 닫는다. 입력 중에는 군단 조작을 잠시 차단한다. 기본 채널은 **근접**이고, **전체**로 전환하면 현재 같은 방의 접속자에게 전달한다.
- 근접 수신 범위는 서버가 계산한 군단 중심 거리 **80m 이하**다. 시야에 발신자 유닛이 있는 수신자에게만 관측 가능한 유닛 ID를 붙여 말풍선을 표시한다. 시야 밖 발화는 로그에만 나타나며 패킷에 발신 좌표를 넣지 않는다.
- 서버가 발신자 이름을 세션에서 가져온다. 공백만 있는 입력, 제어 문자, **100자 초과** 메시지를 거절하고 전체 **3초**, 근접 **1초** 쿨타임을 적용한다. 방 제목과 채팅은 일반 텍스트로 렌더링한다. 채팅을 전투 명령 큐와 분리하고 접속 종료 시 로컬 채팅 로그를 지운다.
- 채팅 숨기기, 발신자 차단, 메시지 신고를 제공한다. 온라인 신고는 서버가 해당 참가자에게 실제로 전달한 최근 메시지 ID만 받는다. 신고가 접수되면 운영자만 접근할 수 있는 별도 기록에 해당 메시지와 신고 사유를 보관한다. 보관 기간의 초기값은 **7일**이다. 일반 채팅 본문은 운영 로그에 기록하지 않는다. [채팅 기획](../기획서/Elemental%20Legion%20게임%20기획서.md#서버-규칙)

## 완료 기준과 공개 순서

| 검증 | 통과 조건 |
| --- | --- |
| 두 외부 네트워크 | 다른 공유기에 있는 Windows Player 두 대가 IP 입력 없이 방 제목을 찾아 입장한다. 최소 인원 전 시작을 막고, 방장이 시작하면 양쪽이 같은 전장으로 이동한다. LAN 자동 검색과 기존 직접 주소 접속도 확인한다. |
| 입장·권한 | 인증서 불일치, 만료·재사용 입장권, 다른 방 요청, 비방장 시작, 중복 시작, 정원 경합, 위조 소유자 ID, 잘린·큰 메시지를 거절한다. 한 방의 시야·전투·채팅 정보가 다른 방에 도달하지 않는다. |
| 남용·운영 | 방 만들기와 연결 폭주, 느린 수신, 잘못된 UTF-8, 제목·채팅 마크업, 위조 신고를 주입한다. 방·큐 상한이 지켜지고 다른 참가자의 틱이 멈추지 않는다. 로그에 복귀 키와 입장권이 기록되지 않는다. |
| 복귀·저장 | 같은 이름으로 다른 기지를 가져갈 수 없다. 만료 직전 복귀와 기한 이후의 거절, 공성 패배, 서버 재시작 후 자산·타이머 복원, 한 번만 환불, 손상 파일의 백업 복구를 검사한다. |
| 채팅·성능 | 세 클라이언트로 80m 경계와 시야 밖 발화의 좌표 차단을 확인한다. WSS 지연·패킷 유실, 방당 틱 p99, 클라이언트 대역폭, 저장 복사 비용을 기록한다. |

각 단계에서 실패를 재현하는 테스트를 먼저 추가하고 .NET 전체 테스트를 돌린다. Unity 컴파일과 Windows Player 검증을 분리해 기록한다. 프로토콜은 **v11**로 올려 LAN 입장·복귀·채팅과 온라인 방 접속 계약을 함께 문서화한다. 입장 시 프로토콜 버전과 게임 데이터 해시를 확인한다. [서버 런처](../../Start-Server.cmd)에 **4번 M5 데모**를 추가해 별도 저장 폴더와 7778번 포트를 쓰고, Unity 서버 목록에서도 선택할 수 있게 한다.

공개는 로컬 TLS 검증, 두 외부 네트워크 비공개 테스트, 공개 운영 순서로 진행한다. 마지막 단계에는 공인 도메인·인증서와 호스팅, 외부 트래픽 제한, 백업 복원 확인이 필요하다. 이번 문서는 구현 계획이며 호스팅 선정·배포, Windows Player 실행, 실측은 진행하지 않았다.
