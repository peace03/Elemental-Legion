# M3 피드백에 따른 UI와 씬 개선 설계

2026-11-03에 관측소 배치와 플레이어 현황 화면을 확정했다. 설정에 사용자 지정 조작 키를 추가한다.

## 목표와 화면 방향

메인 월드에서 지형을 가리는 시야 표현을 없애고, 탐색 기록은 미니맵에서 보여 준다. 수비대의 집결 진행을 HUD와 미니맵에서 함께 알린다. 접속·설정·상세 현황을 전투 화면에서 분리해 군단과 교전 위치를 읽기 쉽게 만든다.

시안은 같은 화면 흐름을 두 배치로 비교한다. 수치·배치·진행 시간은 화면 검토용 예시이며 서버 판정이나 새 밸런스가 아니다.

| 시안 | 배치와 용도 |
| --- | --- |
| 관측소 | 왼쪽에 미니맵과 군단 정보를 모으고 오른쪽에 양성·집결 명령을 둔다. 양성 목록은 필요할 때 펼친다. |

원소의 청록·보라 표현과 기존 한글 폰트를 이어 간다. 버튼·여백·테두리·선택 상태·정보 우선순위를 통일한다. 아군·적·중립은 색뿐 아니라 원·삼각형·마름모 등 형태와 이름으로도 구분한다. 강한 움직임은 집결 시작·합류·경고 같은 상태 변화에만 사용한다.

## 현재 구현에서 확인한 점

- [FogOfWar.shader](../../client/Assets/_Project/Shaders/FogOfWar.shader)의 `Composite`가 미탐색 지역을 검게 덮고, 탐색했지만 현재 시야 밖인 지형을 어둡게 만든다. 메인 카메라에도 탐색 정보가 적용되는 직접 원인이다.
- [FogPresentation](../../client/Assets/_Project/Scripts/Runtime/FogOfWar/FogPresentation.cs)이 플레이어별 현재 시야·누적 탐색 마스크를 이미 받는다. 미니맵은 이 상태를 재사용할 수 있다.
- [CombatHud](../../client/Assets/_Project/Scripts/Runtime/UI/CombatHud.cs)는 핵·인구·구성·양성·14종 버튼을 표시하고, [M3SceneSetup](../../client/Assets/_Project/Scripts/Editor/M3SceneSetup.cs)은 음량 패널까지 전투 화면에 배치한다.
- [ClientBootstrap](../../client/Assets/_Project/Scripts/Runtime/Bootstrap/ClientBootstrap.cs)이 접속·명령·수신·입력·표현을 연결한다. 화면 전환 때 새 접속 객체를 만들지 않도록 이 소유권을 유지해야 한다.
- 초기 M3에서는 집결 여부를 서버 내부에만 보관했다. 버튼 입력 직후 표시를 확정하면 명령 거절이나 합류 완료와 어긋날 수 있다.
- 현재 시작 씬은 `Legion.unity`다. 타이틀·서버 목록·설정·플레이어 현황 전용 씬은 없다.

## 메인 월드와 미니맵

### 메인 월드

- 카메라에 들어온 지형과 배경은 탐색 여부와 관계없이 보인다. 월드 전체를 한 화면에 축소하는 요구로 해석하지 않는다.
- 미탐색 검정 차폐와 탐색 지역 밝기 저하는 메인 카메라에서 제거한다. 장식용 연무를 유지하더라도 탐색 정보로 지형을 덮지 않는다.
- 시야 밖 적 유닛·적 건물·핵·전투 효과·소리는 계속 서버 필터를 따른다. 지형이 보인다는 이유로 숨은 개체나 마지막 위치를 복구하지 않는다.
- 기존 셰이더와 Renderer Feature를 통째로 삭제하지 않고, 장식용 월드 표현과 미니맵의 탐색 표시를 분리한다.

### 미니맵

- 미탐색은 가림, 탐색했지만 현재 시야 밖인 지형은 어둡게, 현재 시야는 선명하게 표시한다.
- 내 군단·내 본진·내 수비대를 구분한다. 적과 중립 아이콘은 현재 허용된 관측만 사용하며 Forget·연결 종료 즉시 제거한다.
- 집결이 진행 중일 때는 본진과 내 군단 사이에 방향을 나타내는 점선을 그리고 `집결 중…`을 표시한다.
- 미니맵은 전용 소형 텍스처와 재사용 아이콘을 사용한다. 매 프레임 전체 월드를 탐색하거나 별도 게임 시뮬레이션을 돌리지 않는다.
- 미니맵 클릭 이동·숨은 적 경보·과거 적 위치 표시는 이번 범위에 넣지 않는다.

## 수비대 집결 표시

표시는 `대기 → 명령 확인 중 → 집결 중 → 합류 완료`로 구분한다. 거절되면 이유를 표시하고 대기로 돌아간다.

- 자기 상태에 집결 활성 여부를 추가한다. 화면의 `집결 중` 조건은 **마지막 집결 명령을 받은 수비대가 아직 이동 중일 때**다. 본진 근접 자동 합류를 제거하고 명령 이후 양성된 유닛은 다음 명령을 기다린다.
- HUD와 미니맵에는 `집결 중…`을 표시한다. 도착을 서버에서 확인하면 `합류 완료`를 짧게 보여 준다. 상단 수비대 수에는 대기 중인 유닛도 포함한다.
- 수비대가 없으면 집결 버튼을 비활성화한다. 이미 진행 중이면 같은 명령을 반복 전송하지 않는다.
- 명령 접수와 서버 실행 상태를 구분하며, 이동 명령 응답과 집결 명령 응답을 sequence로 구별한다. 재접속·연결 종료 때 대기 표시를 초기화한다.
- `WorldView → GameplayCodec/GameplayFrame → GameplayReplica → HUD/미니맵`을 함께 바꾼다. 패킷 필드가 추가되므로 프로토콜 버전과 [프로토콜 문서](../protocol.md)를 함께 갱신하고, 예전 클라이언트·서버의 조합은 명확히 거부한다.

## 씬과 화면 흐름

| 씬 또는 화면 | 역할 |
| --- | --- |
| `Bootstrap.unity` | 사용자에게 별도 화면으로 노출하지 않는다. 화면 전환과 공용 설정을 연결한다. |
| `Title.unity` | 게임 시작, 설정, 게임 종료. |
| `ServerBrowser.unity` | 저장된 서버 목록, 주소 직접 등록, 시작 원소 선택, 접속·오류·다시 시도. |
| `Legion.unity` | 기존 월드와 군단 표현을 유지하고 새 HUD·미니맵을 연결한다. |
| 인게임 ESC 메뉴 | 계속하기, 설정, 종료하기. 종료하기에서 타이틀 복귀와 게임 종료를 분명히 구분한다. |
| `Settings.unity` | 타이틀과 인게임에서 같은 설정 화면을 연다. 닫으면 열었던 화면으로 돌아간다. |
| `PlayerDashboard.unity` | 현재 플레이어의 군단·자원·양성·전향 통계와 구성. 닫으면 인게임으로 돌아간다. |

일반 흐름은 `타이틀 → 서버 목록 → 접속 중 → 인게임`이다. 접속 실패 시 선택한 주소·원소를 유지한 서버 목록으로 돌아가 이유와 재시도를 제공한다. 접속 중 취소와 늦게 도착한 응답도 처리한다.

설정과 플레이어 현황은 필요한 씬을 **추가 로드**한다. 기존 인게임 씬을 유지해 소켓·카메라·시야·통계가 재생성되지 않게 한다. 한 화면만 입력을 받으며, EventSystem과 AudioListener도 중복 생성하지 않는다. Unity는 추가 로드를 기존 씬을 유지하는 방식으로 제공한다. [Unity Additive 문서](https://docs.unity.com/en-us/engine/6000.6/script-reference/unityengine/scenemanagement/loadscenemode/additive)

접속과 수신의 소유자는 활성 인게임의 `ClientBootstrap` 한 곳으로 유지한다. 화면 전환 조정 객체에 전투 판정이나 두 번째 네트워크 세션을 넣지 않는다. 타이틀 복귀·게임 종료 시 연결과 구독을 정리한다. `Legion` 단독 Play의 기존 진입 경로도 유지한다. `SampleScene`과 `ElementGallery`, 기존 프리팹 GUID·씬 참조는 보존한다.

온라인 서버는 ESC 메뉴·설정·현황 화면을 열어도 계속 진행한다. 로컬 이동·집결 입력은 차단하고 이동 방향 0을 정상 전송하며 수신과 표시 갱신은 유지한다. 메뉴에는 이 점을 짧게 알린다. `Time.timeScale=0`으로 온라인 전투를 멈춘 것처럼 만들지 않는다.

## HUD와 플레이어 현황

상시 HUD에는 핵·현재/예약/최대 인구·수비대·양성 진행·집결 상태·미니맵을 남긴다. 14종 양성 버튼은 접이식 패널에 모으고 원소명·비용·시간·잠금 이유를 유지한다. 음량 설정과 긴 통계는 전투 화면에서 뺀다.

현황 화면은 현재 접속한 플레이어의 정보를 다음처럼 묶는다.

- 군단: 원소별 수, 총 인구, 예약 인구, 수비대와 집결 상태.
- 경제와 성장: 핵, 본진 레벨, 현재 양성 원소와 진행.
- 이번 접속 통계: 양성 횟수, 전향 횟수, `전향 / (양성 + 전향)` 비율. 초기 3기는 분모에서 제외하며 분모 0은 `집계 없음`이다.

현재 서버가 주는 자기 상태를 재사용한다. 상대 경제나 시야 밖 적 위치를 넣지 않는다. 계정·월드 저장이 아직 없으므로 통계를 영구 누적 기록처럼 표현하지 않는다.

## 설정

| 분류 | 포함할 항목 |
| --- | --- |
| 음향 | 전체·효과음·UI 음량과 각 음소거. 기존 음향 풀을 재사용한다. BGM이 없으므로 작동하지 않는 BGM 슬라이더는 만들지 않는다. |
| 화면 | 지원 해상도, 창 모드·테두리 없는 전체 화면, 수직 동기화, 프레임 제한. VSync 사용 시 적용되지 않는 프레임 제한은 비활성 이유를 보여 준다. |
| 표현과 가독성 | 기존 연무 품질, UI 크기, 과한 UI 동작 줄이기. 색 외의 아군·적·중립 구분도 유지한다. |
| 조작 키 | 이동의 기본·보조 키 네 방향, 집결, 메뉴 키를 각각 지정한다. 충돌 안내, 입력 취소, 기본값 복원, 로컬 저장을 제공한다. HUD에는 현재 집결·메뉴 키를 표시한다. Enter는 UI 선택에 예약한다. |

음량은 즉시 미리 듣고 저장한다. 화면·품질·UI 설정은 적용 전에 바뀐 값을 구분한다. 해상도·창 모드 변경은 유지 확인을 받고, 15초 이내 확인하지 않으면 기존 상태로 복구한다. UI 크기는 현재 해상도에서 핵심 조작이 잘리지 않는 범위만 허용한다. 설정은 로컬 `PlayerPrefs` 등 기존 플랫폼 저장 기능으로 보존하며 M5의 서버 월드 저장과 섞지 않는다. 화면 변경 API와 지원 조건은 [Unity SetResolution 문서](https://docs.unity.com/en-us/engine/6000.6/script-reference/unityengine/screen/setresolution)를 따른다.

## 재사용 조사와 채택 방향

2026-11-03 확인했다. 이번 단계에서는 외부 코드·스킬·에셋을 설치하거나 게임에 가져오지 않는다.

| 자료 | 확인한 내용과 판단 |
| --- | --- |
| [Kenney UI Pack Sci-Fi](https://kenney.nl/assets/ui-pack-sci-fi) | 공식 페이지에 CC0·무료 배포가 표시된 버튼·패널·슬라이더 자료다. Unity 표현용 스프라이트 후보로 삼고, 시안 확정 후 필요한 부분만 임포트·아틀라스화·한국어 조합을 검증한다. 전체 라이브러리를 넣지 않는다. |
| [Unity uGUI](https://github.com/Unity-Technologies/uGUI) | 현재 사용하는 Canvas 기반 UI를 유지한다. 자동 배치·앵커·공통 스타일을 정리하며 다른 UI 프레임워크를 새로 넣지 않는다. |
| [Unity UI 스킬](https://github.com/Unity-Technologies/skills/blob/main/skills/ui/SKILL.md) | 현재 제공된 `unity:ui`와 `unity:ui-ugui`를 적용한다. 계층·이벤트·해상도·참조 보존 검증에 활용한다. |
| [Game UI Design 스킬](https://github.com/jeremylongworth-source/AgentSkills/blob/main/skills/game-ui-design/SKILL.md) | 원본과 저장소 MIT 라이선스를 확인했다. 정보 우선순위·로딩/오류/잠금 상태·키보드·해상도 검토를 설계 참고로 활용한다. 로컬 스킬로 설치하지 않는다. |
| [OpenAI Game UI Frontend](https://github.com/openai/plugins/blob/main/plugins/game-studio/skills/game-ui-frontend/SKILL.md) | 브라우저 게임용이므로 Unity 구현을 그대로 가져오지 않는다. 전장 중앙 확보, 드문 기능 접기, 메뉴와 게임 입력 경계 원칙을 참고한다. |

기존 uGUI를 유지하며 씬을 나누는 방식을 추천한다. 전체 UI Toolkit 전환은 현재 프리팹·TMP·음향·입력 연결을 다시 만드는 비용이 크고 이번 피드백 해결에 필수적이지 않다. UI를 한 씬의 패널로만 바꾸는 방식은 변경량은 작지만 사용자가 요청한 씬 분리를 충족하지 못한다.

실제 외부 자료 도입 시에는 고정 버전·라이선스·원본·사용 경로를 [외부 자료 규칙](../Rules/reuse.md)에 따라 별도로 기록한다.

## 반영 순서와 검증 기준

1. 시안에서 배치·스타일과 화면 흐름을 확정한다. 예시 데이터와 실제 서버 상태를 구분한다.
2. 메인 월드의 탐색 차폐를 제거하고 현재/누적 시야를 사용하는 미니맵을 연결한다. 시야 밖 개체의 패킷 차단·Forget 회귀 테스트를 유지한다.
3. 자기 집결 상태의 공유 뷰·직렬화·수신·HUD·미니맵을 함께 연결한다. 대기·진행·완료·거절·연결 종료·다음 양성의 상태를 테스트한다.
4. 기존 uGUI와 자산 참조를 보존하며 타이틀·서버 목록·공용 설정·ESC 메뉴·현황 씬을 연결한다. 접속 취소·실패·재시도·설정 복귀·빠른 반복 전환을 검증한다.
5. 1280×720, 1920×1080, 2560×1440과 UI 확대 상태에서 텍스트·버튼·드롭다운·미니맵·키보드 포커스를 확인한다. 양성 패널을 펼쳐도 전장 중앙을 가리지 않게 한다.
6. .NET 전체 빌드·테스트, Unity 컴파일·EditMode, 필요한 실제 Play·Windows Player 검증을 구분해 보고한다. 이전 M3 검증 결과를 새 UI의 검증으로 대신하지 않는다.

원본 기획서의 「조작과 시야」에는 메인 월드/미니맵 구분 없이 안개가 적혀 있다. 이번 사용자 피드백을 우선하며, 구현 시 그 절과 아키텍처·M2 테스트 설명을 함께 좁혀 갱신한다. 서버 시야 반경과 밸런스는 바꾸지 않는다.

적 피드백은 미확인 상태로 남긴다. 두 클라이언트가 같은 서버에 접속해 시야 진입·교전·이탈을 확인하는 경로를 검증 항목에 넣는다. 기존 1인 M3 데모의 중립 유닛을 적 플레이어 검증으로 간주하지 않으며, 시안에 그린 적 표시는 실제 게임 검증이 아니다. 무단으로 적 봇을 실제 월드에 추가하거나 시작 규칙을 바꾸지 않는다.

## 구현 담당자가 정할 세부 사항

씬 로딩 조정 클래스의 구체적인 이름, 공통 UI 프리팹을 나누는 단위, 스프라이트 후보의 세부 선택, 미니맵 픽셀 수와 아이콘 풀 용량은 위 계약과 기존 성능 규칙 안에서 결정한다. 메인 월드의 지형 표시, 서버 시야 차단, 메뉴 중 연결 유지, 집결 표시의 서버 근거는 변경하지 않는다.

## 시안 검토와 검증 상태

독립 설계 검토에서 구현 계획 전에 반드시 추가 확인할 중요한 빈틈은 발견되지 않았다. 최종 배치와 스타일은 사용자 검토 대상으로 남긴다.

브라우저 시안의 두 배치에서 타이틀·서버 목록·인게임·설정·현황 전환, 빈 주소 입력, HUD/미니맵 집결 중 표시와 합류 완료, 메뉴 중 이동 입력 차단, 설정 되돌리기, 360px 화면의 가로 넘침을 자동 확인했다. 군단 이동으로 적 표시가 사라져도 메인 지형은 유지되는 것을 확인했다. 데스크톱 타이틀·인게임 두 배치와 작은 화면의 설정을 이미지로 확인했다. 시안에는 실제 서버 접속·전투·OS 해상도 변경을 연결하지 않았다.

위 확인은 시안 검증 결과다. 승인 이후 Unity 적용 범위와 결과는 별도 구현 계획과 검증 기록을 따른다. [구현 계획](2026-11-03-observatory-implementation.md)
