## 현재 운영 범위

| 항목 | 기준 |
| --- | --- |
| 방 목록과 공개 범위 | LAN은 같은 네트워크에서 검색한다. 플레이어가 여는 인터넷 방은 HTTPS/WSS 운영 중계를 거치며, 공개 또는 숫자 비밀번호 방으로 열 수 있다. 운영자가 상시 월드를 인터넷 목록에 표시할 수도 있다. |
| 재접속 | 같은 계정은 살아 있는 유령 본진으로 돌아갈 수 있다. 시작한 방에서는 기존 참가 자격도 필요하다. 유령 만료는 진행 중인 월드 시간 600초 기준이다. |
| 저장 | 일반 서버와 운영 서버가 판정하는 방은 체크포인트를 사용한다. 일반 설정은 60초마다, 그리고 정상 종료 시 저장한다. 미종료 LAN 방은 호스트가 다시 열 수 있다. |
| 인터넷 방 승계 | 남은 사람이 있으면 중계가 다음 서버를 선택한다. 정상 퇴장은 마지막 틱을 넘기고, 장애는 최신 검증 백업으로 복구하므로 진행이 되돌아갈 수 있다. 마지막 사람이 나가거나 해당 중계가 종료되면 그 방의 운영이 끝난다. |
| 채팅과 신고 | 근접·전체 채팅, 로컬 발신자 차단을 지원한다. 운영 서버가 판정하는 방은 신고를 접수하며 신고 본문 보관 기간은 7일이다. |

운영 주소와 인증 정보는 서버 환경에서 관리한다. 참가자는 같은 프로토콜과 게임 데이터 해시를 사용하는 빌드로 접속한다. 실제 배포 순서와 외부망 확인 조건은 운영 안내에 있다. [README 온라인 운영](../../../README.md#온라인-서버-운영) · [서버 승계 규칙](../../Rules/architecture.md#인터넷-방-서버-승계) · [공개 전 검증](../../Reports/2026-11-03-m5-validation.md#공개-전-확인)

## 출시 이후 구상과 미결

- 원본은 **능력치에 영향을 주지 않는 치장 보상**을 방향으로 삼고, 계정 레벨, 누적 플레이에 따른 원소 해금, 스킨, 업적·칭호, 일간·주간 순위를 구상한다. 현재 접속 순위와 별개인 보상 체계다. [원본 진행·보상 기획](../Elemental%20Legion%20게임%20기획서.md#진행온보딩아트) · [경제·성장](08-economy-progression.md)
- 근원이 깨어난다는 세계관 설정은 시즌 이벤트에 활용할 여지로 남아 있다. 시즌 일정과 종료 규칙, 보상 표, 판매 정책은 미결이다. [세계관·내러티브](07-world-narrative.md)

## 근원 쟁탈전 운영 개편안

아래는 기존 서버 운영 사실과 구분되는 신규 유한 경기 모드의 운영 제안이다. 아직 판 상태의 저장, 재접속, 승계, 외부망 부하를 이 모드 기준으로 검증한 결과는 없다. 모든 시간과 인원 수는 시험값이다.

### 방 흐름과 경기 수명

근원 쟁탈전은 기존 LAN 또는 인터넷 방에 붙는 최대 12분의 2~15인 개인전이다. 시작할 때 참가 자리를 확정한다. 기존 참가자는 경기 종료 전 최대 60초 동안 같은 신원으로 복귀할 수 있다. 유예 중 원소는 자동 방어하며 관문 점유 자격은 중단된다. 유예 만료와 명시적 포기는 해당 자리의 탈락으로 처리한다.

마지막 사람의 연결만 끊겼고 판 서버가 살아 있으면 복귀 유예 동안 경기를 진행한다. 마지막 사람이 명시적으로 나가거나 유예가 끝났거나, 호스트 장애 뒤 복구 가능한 후보가 없으면 방을 종료한다. 이미 확정된 경기 결과는 보존하고, 아직 결과가 없으면 승자 없음으로 기록한다. 기존 지속 월드는 성장·저장 규칙을 체험하는 연습 공간으로 둔다.

인터넷 방의 정상 인계는 최종 틱, 장애 복구는 최신 검증 백업을 기준으로 한다. 경기 ID마다 결과를 한 번 확정한다. 새 모드의 경기 시계, 본진 재점화, 이탈 유예와 관문 진행은 별도 통합 검증에서 확인한다. 장애 백업 복구에 따른 되돌림은 기존 운영 경계로 취급한다.

종료 화면에는 즉시 재경기 선택을 제공한다. 선택하면 같은 방의 대기실로 돌아가고 참가자는 다시 준비한다. 재경기가 시작되면 원소, 시설, 자원, 점유 상태, 임시 경기 기록을 초기화한다. 참가자가 모두 다시 준비하지 않으면 새 판을 자동으로 시작하지 않는다. 이는 계정 성장이나 영구 통계를 초기화한다는 의미가 아니다.

### 결과와 보상 경계

승패는 모드 문서에 정한 두 관문 연속 단독 점유, 제한 시간 종료 시의 관문 수 및 마지막 60초 누적 단독 점유 시간, 동률 공동 무승부, 전원 탈락 예외로만 결정한다. 킬·점수·누적 승리는 조기 경기 보너스나 계정 경험치로 바꾸지 않는다. 경기 중 얻는 원소와 자원은 해당 경기의 전술적 이득에 한정한다. 현재 운영안의 치장 보상·레벨·해금·순위 구상은 역사 문서로 유지되며 이 모드의 확정 보상으로 확대 해석하지 않는다.

경기 결과 요약은 승리·패배·공동 무승부와 관문 결과를 재경기 전까지 보여 주는 수준으로 시작한다. 신고와 제재를 위해 경기 기록을 저장할지, 보존 기간과 표시 통계를 어떻게 둘지는 결정되지 않았다. 기존 신고 본문 7일 보관 규칙을 자동으로 경기 이벤트 로그 전체에 적용한다고 보지 않는다. 개인정보와 시야 정보 최소 공개는 그대로 적용한다.

### 규모 확장과 운영 확인 순서

운영 검증은 2~4인 방에서 경기 시작·종료, 재접속 제한, 재경기 초기화를 먼저 확인한다. 다음으로 8인 조건에서 호스트 승계와 경합·봉인 판정을 확인하고, 통과 뒤 15인 조건을 확인한다. 15인 단계에서는 패킷량, 서버 틱 지연, 미니맵·음향 알림 수, 승계 복구 시간 및 최악 조건의 동기화를 측정한다. 현재의 15인 색상 팔레트 검증이나 다른 방의 부하 테스트만으로 이 모드 규모가 검증됐다고 판단하지 않는다.

배포 후에도 우선 2~4인으로 열고 오류율, 이탈 및 재접속, 판 길이, 동률 비율, 1인 선점 승률, 본진 무력화 뒤 재점화율과 승리 전환을 관찰한다. 8인과 15인은 앞 단계 운영 자료와 서버 비용을 검토한 뒤 순차적으로 연다. 관문 유지 시간과 원소 수용량은 시험값이며 실제 관측에 맞춰 조정한다. 성능과 밸런스 통과 조건은 [플레이테스트](12-playtest.md)와 [수치 밸런스](09-balance.md)에서 정한다.

현재 LAN 방 저장, 기존 인터넷 방의 주기 저장 및 호스트 승계는 별도 운영 경로다. 신규 경기의 정확한 상태 저장 주기, 승계 실패 시 처리, 재접속 자격 검증, 통계 보존 기간, 공개 방의 단계별 개방 기준은 운영 전에 정해야 한다. 기존 온라인 운영·보안 경계와 프로토콜을 바꾸게 되면 근거 문서도 함께 갱신한다. [시스템 기획](03-systems.md) · [모드·승패](05-modes.md) · [레벨 디자인](06-level-design.md) · [UI·UX 기획](10-ui-ux.md)
