## 개편안 검증 순서

먼저 2~4인 전장을 장식 없이 만들고 시작 핵, 수비대 이동·귀환, 재점화, 관문 2곳 점유까지 한 판에서 시험한다. 시작 자리·주력 원소를 바꿔 같은 조건을 반복하고, 고정 시드 자동 검증과 사람이 직접 겪은 결과를 구분한다. 아래 시간과 비율은 시험 기준이다. [수치 밸런스](09-balance.md)

| 확인 영역 | 테스트와 기록 | 통과 기준 |
| --- | --- | --- |
| 첫 성장 | 처음 보는 사람이 기본 조작만 보고 시작한다. 첫 핵·전향·양성 완료, 목적 분대 지정, 다음 목표 선택까지 걸린 시간을 기록한다. | 첫 보상 중앙값 15초 이내. 첫 30초 안에 도움 없이 분대 한 곳으로 증원을 보낼 수 있는지 확인한다. |
| 본진 방어 | 초반과 결전 직전 각각 원정 중인 만피 본진을 공격한다. 타워·수비대·자기권, 분대의 교전 여부, 여러 공격자의 동시 공성을 나눈다. | 첫 피해에서 자기 HUD 경보까지 p95 1초 이하를 시험한다. 행동 가능한 경우 6초 안에 수비대 이동이나 귀환 완료까지 가능한지 확인한다. 공유 피해 예산과 20초 재점화는 서버 틱 기준으로 검증한다. |
| 원소 배치 | 세 분대를 다른 목표에 놓고 4번 수비대를 옮긴다. 실제 성장 판의 2·6·9분 생존 병력과 준비된 최대 200기 밀집을 별도로 기록한다. | 선택과 실제 명령 대상을 일치시킨다. 전멸 없이 성장한 판에서 결전 시작 무렵 100기 안팎을 운용할 수 있는지 확인한다. 예약 상한·중복 생성과 색을 제외한 분대 식별도 검증한다. |
| 후반 역전 | 8:00에 야전 병력이 상대의 절반 이하인 쪽을 정한다. 상대가 한 관문에 모이거나 두 곳을 분산 방어하는 상황을 각각 시험한다. | 전자의 경우 열세가 다른 두 곳으로 봉인하거나 6기 분대로 상대 봉인을 끊는 합법 경로를 재현한다. 후자의 경우 앞선 쪽의 분산과 방어가 실제 이점이 되는지 비교한다. |
| 마감·공정성 | 12:00 직전 1기 손실로 점유 조건이 바뀌는 경우, 동시 경합, 마지막 60초 점유 역전, 동률, 이탈 후 재접속을 재현한다. | 서버와 결과 화면의 판정이 일치해야 한다. 2~15인 도면에서 두 번째로 가까운 관문의 기하 접근 시간 격차 2.5초 이내를 시험하고, 진형과 장애물이 있는 실제 이동·자리별 승률도 기록한다. |
| 재도전 | 결과에서 승패 사유와 다음 판 준비로 이어지는 흐름을 본다. | 결과에서 왜 졌는지 설명할 수 있는지, 다음 판에서 바꿀 판단이 있는지, 재경기를 실제 선택하는지 기록한다. |

후반 지표는 8분 병력 격차별 최종 승자, 봉인 중단 횟수, 12분 마감·무승부 비율로 나눈다. 단순 접속 시간보다 **목표를 고르고 성공을 읽었는지**를 확인한다. 15인에서 경합만 반복된다면 분대당 화력을 먼저 올리기보다 관문 진입 방향과 점유 반경을 같은 시드에서 비교한다. [승패 규칙](05-modes.md) · [전장 설계](06-level-design.md)

### 개편안의 구체 재현 시나리오

아래는 규칙의 실효성을 확인할 시험 절차이며 통과 기록이 아니다. 문서에서는 행동과 판정 조건의 일치를 확인하고, 이동·생존·경보 인지와 조작 시간은 개편안 구현 뒤 Unity Play와 Windows Player에서 잰다.

1. **열세의 우회와 봉인 중단.** 2인 경기 8:00에 한쪽 야전 병력을 상대의 절반 이하로 두되 두 분대는 각각 점유에 필요한 6기 이상을 유지한다. 9:00에 우세 쪽이 한 관문에 모이면 열세 쪽은 나머지 두 곳으로 나눠 이동한다. 같은 상태에서 우세 쪽이 두 곳을 분산 방어하는 경우와 비교한다. 상대가 봉인 중일 때는 한 관문에 같은 분대 중심과 6기를 진입시키고, 같은 틱 전투 뒤 6기가 남는 경우와 1기가 죽어 5기만 남는 경우를 나눈다. 경합이 성립한 틱의 봉인 초기화, 다른 관문을 확보한 시각, 우세 쪽의 차단·재배치에 따른 실패를 기록한다. 봉인 중단만으로 역전 성공으로 세지 않고 열세 쪽의 실제 최종 승리까지 구분한다. 플레이어는 직접 관측한 적 관문 상태로 판단하며, 상대 봉인 시각은 시험 기록으로만 대조한다.
2. **본진 습격 중 수비 지휘와 귀환.** 두 야전 분대를 원정시킨 채 만피 본진을 공성한다. 경보 뒤 4번 수비대를 공격 경로로 옮기고, 야전 분대를 골라 귀환한다. 선택 분대가 3초 시전 중 피해를 받는 경우와 다른 비전투 분대를 고른 경우를 비교한다. 본진 피격만으로는 귀환이 취소되지 않아야 하며, 분대 피격으로 취소되면 5초 공유 대기시간을 표시해야 한다. 다른 분대의 기존 명령이 유지되는지, 수비 이동과 귀환 병력이 실제로 공격을 막았는지, 첫 피해부터 개입까지 걸린 시간과 남은 본진 체력을 함께 기록한다. 귀환 구역이 막힌 경우도 반복해 배치 실패를 성공으로 표시하지 않는지 확인한다.
3. **첫 무력화 뒤 남은 병력의 재기.** 같은 공성에서 본진을 처음 무력화하고, 야전·수비대·합류 중 증원이 각각 마지막 생존 1기인 경우와 모두 0기인 경우를 나눈다. 20초 뒤 생존 1기가 있으면 보충 예약이 없고, 모두 0기일 때만 1번 분대 8기가 한 번 예약되는지 확인한다. 살아 있는 원소와 시설·핵이 유지되는지, 남은 원소 지휘와 재점화 뒤 양성·증원으로 점유 가능한 분대를 다시 만들 수 있는지 기록한다. 무료 보충이 없는 경우의 재건 시간과 자원 부족도 남기며, 0기인 경우 집결점이 막혔다가 열려도 보충이 중복되지 않는지 확인한다.

### 판정과 정보 경계

- 적 소유 분대 명령, 전장 경계 밖 목적지, 수비대의 본진 반경 밖 목적지, 예약 초과, 이전 연결의 중복 명령은 서버에서 거부한다. 소유한 야전 분대는 전장 경계 안에서 관문 밖으로도 이동할 수 있으며, 관문 밖 이동과 점유 자격은 따로 판정한다. 건물·지형·분대 배치가 불가능할 때는 명령 또는 배치 실패를 알려 주고, 오류에 숨은 적의 좌표나 종류를 담지 않는다.
- 두 분대가 다른 관문을 점유한 상태, 동일 분대의 중복 집계, 정확히 6기와 5기, 이동 중 증원, 경합 1틱, 경기 종료 직전 귀환과 재점화, 이탈 중 관문 영향을 고정 입력으로 재현한다. 본진에 공격자가 여럿일 때 공유 피해 예산이 하나로 적용되는지도 확인한다.
- 승계와 재접속에는 경기 시계, 종료 여부, 봉인·점유 기록, 귀환·재점화, 분대별 인구와 대기열을 포함해 비교한다. 자동화 결과와 Unity Play·Windows Player·별도 회선에서 사람이 본 경보를 구분한다. [운영과 복구](13-live-operations.md) · [보안 규칙](../../Rules/security.md)

## 인원과 병력 규모 검증

| 단계 | 플레이어 상한 부하 | 중립 최대 | 유닛 합계 |
| --- | ---: | ---: | ---: |
| 4인 첫 검증 | 800 | 192 | 992 |
| 8인 확대 | 1,600 | 384 | 1,984 |
| 15인 목표 | 3,000 | 720 | 3,720 |

현행 유닛 표현 상한은 4,096기다. 15인 합계가 그보다 작아도 밀집 전투, 시야 갱신, 전송, UI·그래픽 비용은 별개다. 현행 24B 유닛 레코드로 3,720기를 한 클라이언트가 10Hz로 관측한다는 산술값은 본문만 약 893kB/s다. 패킷 헤더·재전송·전투·시설 데이터는 별도다. 기존 공간 조회, 관심 영역 전송, 표현 풀을 사용하고 실제 관측 개체 수와 송수신량을 잰다. [프로토콜 상한](../../../shared/Runtime/Net/Protocol.cs) · [복제 프레임 상한](../../../shared/Runtime/Net/GameplayCodec.cs)

인원 확대는 동일 시드의 분산과 전원 밀집에서 **20Hz 틱 p99 50ms 이하**, 프레임 한도 초과와 예상 밖 연결 종료 0건을 확인한 뒤 진행한다. 시뮬레이션·시야·프레임 인코딩 시간을 분리하고, 기존 M0의 시뮬레이션 p99 10ms 목표도 비교 지표로 남긴다. Windows Player에서는 목표 해상도와 장비를 기록하고 화면 p95 프레임 시간과 200기 이상 밀집에서 식별성·조작 응답을 확인한다. 15인 공개는 실제 WAN·손실과 서버 승계까지 검증한 뒤 판단한다. [성능 규칙](../../Rules/performance.md) · [M6 측정 범위](../../Reports/2026-11-03-m6-validation.md)

## 기록 방법

방 유형과 시작 인원, 사람·AI 구성과 난이도, 맵 크기, 게임 데이터 버전·해시를 한 회차에 같이 남긴다. 같은 조건에서 시작 위치와 주력 원소를 바꿔 결과를 비교한다. 초반 조우 시간과 새 원소 중 전향·양성 비율은 원본의 확인 항목이며, 위 표의 관측은 이번 플레이 피드백을 확인하기 위한 항목이다. 수치의 목표 범위와 실제 체감은 사람 플레이 결과로 판단한다. [원본 확인 목록](../Elemental%20Legion%20게임%20기획서.md#미결-항목과-확인-목록) · [밸런스](09-balance.md)
